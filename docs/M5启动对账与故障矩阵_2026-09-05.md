# M5 启动对账与故障矩阵验收报告

日期：2026-09-05

## 结论

M5 已完成。Deep Thesis 在应用装配时对任务记录、FSM、正式产物、分节版本、后台 Job 和知识库进行一致性检查；只有产物 Outbox 重放和过期 Worker 租约回收属于自动修复。其他冲突统一返回稳定原因码、阻断数量和只读修复报告，并禁止确认当前环节。

## 已实现能力

- 应用启动时执行全任务对账，报告一致任务数、异常任务数、孤立域记录和已恢复 Job 数量。
- 任务进度与 Resume 复用同一对账结果；异常时显示 `REPAIR_REQUIRED`，不返回正文、证据摘录或内部 Job payload。
- 新增只读任务对账接口：`GET /api/v1/console/tasks/{task_id}/reconciliation`。
- 健康检查增加启动对账状态、异常任务数量和全局孤立记录数量。
- 环确认前强制重跑对账；任一阻断项存在时返回 `STARTUP_RECONCILIATION_REQUIRED`。
- Worker 租约过期后在启动或巡检时恢复为 `PENDING`、`FAILED` 或 `CANCELLED`。
- 知识库以注入的实例根目录为准，并只读校验索引结构与已登记文件是否存在。

## 自动修复边界

| 场景 | 行为 |
| --- | --- |
| FSM Outbox 尚未投影正式产物 | 幂等重放，成功后继续 |
| Worker 租约过期且仍可重试 | 清除旧租约并恢复为 `PENDING` |
| Worker 租约过期且达到上限 | 标记 `FAILED` |
| 取消中的 Worker 租约过期 | 标记 `CANCELLED` |
| 任务/FSM 元数据不一致 | 报告并阻止确认，不自动覆盖 |
| 已完成环缺少任务产物或批准产物 | 报告并阻止确认 |
| 已汇编分节缺失或过期 | 报告并阻止确认 |
| 孤立 FSM/Artifact/Section/Job | 记录为全局修复项，不自动删除 |
| 知识库索引损坏或登记文件缺失 | 报告并阻止确认，不静默重建 |

## 故障验收矩阵

| 故障 | 自动化证据 | 结果 |
| --- | --- | --- |
| 应用进程重启 | 持久化 SQLite 仓储重开后重新对账 | 通过 |
| 产物投影中途崩溃 | Outbox 保留并在新编排实例中重放 | 通过 |
| Worker 崩溃/租约过期 | 启动对账回收租约并保留重试次数 | 通过 |
| 重复 Job 提交 | 任务级幂等键返回同一 Job | 通过 |
| 工作区乱序重复提交 | 服务端单调 revision 与同版本冲突检测 | 通过 |
| 页面退出末次保存 | `pagehide` 自动草稿与正式提交状态机回归 | 通过 |
| 任务/FSM 载荷缺失 | Resume 进入 `REPAIR_REQUIRED`，确认被拒绝 | 通过 |
| 孤立跨域记录 | 启动报告稳定域级原因码 | 通过 |
| 知识库索引损坏 | 只读审计报告 `KB_INDEX_INVALID` | 通过 |
