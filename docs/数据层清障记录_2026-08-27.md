# 数据层清障记录（2026-08-27）

## 目标

消除“同一任务/同一表存在多套真相”，让项目能够被安装，并使知识库在无嵌入模型时仍有可用检索能力。本阶段不调用付费模型。

## 已完成

1. ORM唯一事实源
   - 删除`db/models.py`中的旧`t_task/t_fsm_state`及其他未使用业务映射。
   - `db.models`现在仅作为`fsm.state.orm`的兼容导出。
   - `backend/db/ddl.sql`明确标记为早期目标设计，禁止在Alembic基线完成前直接用于生产。
2. 任务API统一
   - 删除`application/tasks.py`的进程内任务字典。
   - `/api/v1/tasks`和`/api/v1/console/tasks`共享`MainOrchestration`、FSM、租户和`_TaskStore`。
   - 安全模式下原生任务API同样执行角色和租户控制。
3. 安装与依赖
   - `backend/pyproject.toml`启用包发现，并打包`prompts/*.md`和内置DOCX模板。
   - 手工构建并隔离安装wheel成功，安装目录可加载提示词与内置模板。
   - 依赖拆为`requirements-runtime.txt`、开发测试`requirements.txt`和可选`requirements-production.txt`。
   - 默认数据库改为SQLite，与README和实际单机运行一致。
4. 知识库检索
   - DOCX段落与表格可进入RAG索引。
   - 增加轻量BM25，与向量余弦按70/30融合。
   - 嵌入模型不可用时自动使用关键词检索，不再直接返回空结果。
   - 检索结果记录`vector_score`、`keyword_score`和`retrieval_mode`。

## 验证

- ORM/任务API/安全定向测试：通过。
- wheel：构建成功，约279KB；隔离安装后提示词和内置DOCX模板均可读取。
- RAG：DOCX抽取、向量+关键词融合、无模型关键词降级测试通过。
- 全量回归：`214 passed, 1 warning in 50.57s`。
- warning仍是FastAPI测试客户端的上游弃用提示，不影响本阶段功能。

## 仍然存在的边界

- `_TaskStore`、FSM、产物、证据、研究和Job仍是多个SQLite文件，尚未形成一个PostgreSQL事务边界。
- PostgreSQL DDL不是当前迁移源；需要建立Alembic初始版本并做SQLite→PostgreSQL迁移演练。
- BM25当前按查询即时计算，适合单机中小知识库；大规模知识库需倒排索引或数据库全文检索。
- `vectors.json`仍是单文件持久化，后续需要分片或迁入数据库。
