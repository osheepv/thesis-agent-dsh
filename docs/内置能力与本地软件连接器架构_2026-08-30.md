# 内置能力与本地软件连接器架构

> 日期：2026-08-30  
> 状态：产品执行基线  
> 适用范围：本地优先、单作者的论文全流程工作台  
> 核心决定：核心体验内置，外部软件可选增强，导入导出永远可用  

## 1. 产品决定

用户不应为了完成论文流程中的某一项常见工作，被迫离开论文工作台、下载另一款软件、重新建立资料库或重复录入数据。

产品必须遵守：

1. 不安装Obsidian、Zotero或其他软件时，论文核心流程仍完整可用。
2. 用户已经使用外部软件时，不要求搬家；在论文工作台内连接并使用其资料。
3. 外部软件只提供资料或通用能力，不能改变十环FSM、审批、证据可信等级和正式产物版本。
4. 外部软件离线、卸载、移动目录或授权过期时，论文项目仍可继续。
5. 用户可以随时导出通用格式，不能被本产品或第三方软件锁定。

准确产品形态是：

    原生学术资料中心
       + 可选本地/云端连接器
       + 通用文件导入导出
       + 高级MCP与用户自有软件接口

外部软件的界面不应成为主流程。用户在论文工作台中搜索、筛选、引用、记笔记、绑定证据和写作；只有用户明确选择“在外部软件打开”时才切换应用。

## 2. 三层能力模型

### 2.1 第一层：产品原生内置

无外部软件时必须提供：

- PDF、DOCX、TXT、Markdown、RIS、BibTeX和CSL-JSON导入。
- 文献题录编辑、DOI核验、去重、标签、分类、排序和纳入/排除。
- PDF阅读、全文搜索、高亮、批注、页码定位和证据摘录。
- Markdown笔记、双链、反向链接、标签、Frontmatter和知识图谱。
- 文献、笔记、摘录、论断、章节和引用之间的关系。
- GB/T 7714、APA等引用样式。
- 正文引用、文末条目、证据原文和页码之间的跳转。
- 本地知识库、RAG、备份、恢复和任务包导出。

现有Knowledge、Evidence、Project Memory、Writing和Cytoscape能力应继续演进为统一的“学术资料中心”，而不是再建一套平行系统。

### 2.2 第二层：官方或本地连接器

用户已有Zotero、Obsidian或其他工具时：

- 自动发现已知的本地服务，但不扫描整机端口。
- 用户选择具体库、Collection、Vault或目录。
- 默认只读连接。
- 写入前展示目标、数量和字段差异。
- 同步状态、最后同步时间和冲突在工作台内显示。
- 外部软件不运行时使用本地快照并等待恢复。

### 2.3 第三层：通用接口

对没有专用适配器的软件提供：

- 授权文件夹。
- REST连接器。
- MCP连接器。
- RIS、BibTeX、CSL-JSON、Markdown、DOCX和PDF导入导出。
- 高级用户可接入自己的本地工具，但默认不执行任意程序。

## 3. Obsidian裁决

### 3.1 不直接捆绑Obsidian本体

Obsidian软件不是可以随意复制进本项目的开源组件。其现行条款将软件定义为许可而非出售，并限制转让、分发、修改和构建衍生软件。没有单独书面授权和许可证审查，不将Obsidian程序、界面或核心代码打进本产品安装包。

官方依据：

- [Obsidian服务条款](https://obsidian.md/terms)
- [Obsidian开发者文档](https://docs.obsidian.md/)

### 3.2 原生实现论文所需的Obsidian体验

本产品内置：

- Markdown编辑。
- 双中括号双链。
- 标题锚点和块引用。
- 反向链接。
- 标签与YAML Frontmatter。
- 附件。
- 局部和全局知识图谱。
- 笔记模板。
- 文献、证据、实验和章节的专用链接。
- 关键词、全文和向量检索。

这些能力服务于论文项目，不复制Obsidian完整插件生态或通用个人知识管理范围。

### 3.3 连接用户已有Vault

Obsidian官方说明Vault是本地文件系统中的普通文件夹，笔记是Markdown纯文本，外部修改后Obsidian会刷新。由此可以采用文件夹连接器，不依赖社区REST插件。

官方依据：

- [Obsidian如何存储数据](https://obsidian.md/help/Files%2Band%2Bfolders/How%2BObsidian%2Bstores%2Bdata)
- [Obsidian Vault管理](https://obsidian.md/help/Files%2Band%2Bfolders/Manage%2Bvaults)

连接步骤：

1. 用户用系统文件选择器选择Vault或其中一个子目录。
2. 产品计算根目录真实路径和Vault指纹。
3. 扫描Markdown、Frontmatter、双链和附件。
4. 默认只读挂载。
5. 用户可选择“导入副本”或“开启双向同步”。
6. 双向写入优先限制在Thesis Agent/项目名称专用目录。
7. 文件监听与定期哈希校验共同发现变化。
8. Vault移动后提示重新定位，不新建空目录冒充原Vault。

### 3.4 在Obsidian中打开

如果用户已经安装Obsidian，使用官方obsidian URI打开、创建、搜索或定位到标题/块。该入口是可选快捷方式，不是核心功能依赖。

官方依据：

- [Obsidian URI](https://help.obsidian.md/Extending%2BObsidian/Obsidian%2BURI)

### 3.5 可选Obsidian插件

最后阶段可发布一个独立社区插件，提供：

- 将当前笔记发送到某论文项目。
- 将选中文本登记为候选摘录。
- 显示笔记关联的论文任务和章节。
- 打开论文工作台中的对应证据或章节。

插件必须单独许可、单独发布，用户自愿安装。产品基础同步不能依赖这个插件。

## 4. Zotero裁决

### 4.1 不把完整Zotero客户端嵌入主程序

Zotero本身具有成熟文献管理能力，但完整客户端及许多相关仓库采用AGPLv3，直接合并到Apache-2.0主项目会增加许可、源代码提供、商标、更新和安装体积成本。

默认采用官方API互操作，不复制Zotero界面，不直接修改zotero.sqlite。

官方依据：

- [Zotero项目](https://github.com/zotero/zotero)
- [Zotero客户端开发说明](https://www.zotero.org/support/dev/client_coding)

### 4.2 Zotero本地API

当Zotero已安装并运行时，后端可连接：

    http://127.0.0.1:23119/api/

官方Local API特点：

- 本地读取不经过云端，可离线、无远程额度。
- 用户必须在Zotero设置中允许本地应用访问。
- Zotero 10及以上的写入需要Zotero弹窗授权。
- 支持条目、集合、附件、全文、搜索和对象版本。
- 返回Zotero-Server-ID，用于区分不同本地实例。
- 本地写入会显示在Zotero中，并在Zotero同步时上传。

官方依据：

- [Zotero Local API](https://www.zotero.org/support/dev/web_api/v3/local_api)

产品行为：

1. 仅探测固定回环地址，不接受任意目标URL。
2. 先请求无副作用健康信息和API版本。
3. 用户选择要连接的Collection。
4. 默认只读增量同步。
5. 写入时调用官方授权流程。
6. 本地写入Key进入系统凭据库，不写数据库、配置和日志。
7. 记录Server ID，不能把两个Zotero实例的版本号混用。

### 4.3 Zotero云端API

没有运行桌面客户端但有Zotero账号时：

- 通过官方授权或用户创建的专用API Key连接。
- 默认申请只读权限。
- 用户选择个人库、群组库和Collection。
- 使用版本号和since游标增量同步。
- 写入使用前置版本条件，冲突进入冲突中心。
- Token进入系统凭据库。

官方依据：

- [Zotero Web API v3](https://www.zotero.org/support/dev/web_api)
- [Zotero Web API基础](https://www.zotero.org/support/dev/web_api/v3/basics)
- [Zotero写入请求](https://www.zotero.org/support/dev/web_api/v3/write_requests)

### 4.4 无安装、无账号降级

永远支持：

- RIS导入导出。
- BibTeX/BibLaTeX导入导出。
- CSL-JSON导入导出。
- Markdown笔记导入导出。
- 附件目录导入。
- 格式化参考文献导出。
- 整个论文资料包导出。

因此用户没有Zotero也不损失核心能力。

## 5. 统一数据映射

| 内部对象 | Zotero | Obsidian |
|---|---|---|
| Task/Knowledge Base | Collection | Vault子目录 |
| SourceRecord | Bibliographic Item | 文献Markdown页 |
| 文献附件 | Attachment Item | PDF或附件 |
| Note | Note Item | Markdown文件 |
| 标签 | Tags | 标签或Frontmatter |
| 关系 | Related Items | 双链 |
| EvidenceExcerpt | Annotation或Note | 带页码引用块 |
| 外部ID | library ID和item key | 相对路径或Frontmatter UUID |
| 外部版本 | item/library version | 内容哈希、大小和mtime |

每个外部映射保存：

    connector_id
    external_instance_id
    external_library_id
    external_id
    external_revision
    content_hash
    last_synced_at

第三方特有字段放在extensions中，不能污染核心领域模型，也不能在格式转换时静默丢弃。

## 6. 同步规则

### 6.1 默认只读

- 新连接默认“导入副本/只读同步”。
- 双向同步必须显式开启。
- 每种对象必须有唯一主数据源。
- Agent不能自行开启双向同步。

### 6.2 版本与冲突

- 使用版本号、游标、内容哈希和幂等键。
- 两侧同时修改时禁止最后写入者覆盖。
- 冲突中心允许：保留工作台版、保留外部版、两者都保留或手工合并。
- 外部删除默认标记失联，不自动删除本项目资料。
- 已进入正式证据链的外部变化创建待复核新版本。
- 外部有题录不能自动升级为全文证据已核验。

### 6.3 离线

- 显示最后同步时间。
- 显示当前使用本地快照。
- 写入进入Outbox。
- 恢复连接后幂等重放。
- 外部软件故障不能阻塞论文FSM。

## 7. 通用连接器架构

    工作台UI / 论文Agent
              |
       权限与工具网关
              |
        内部统一数据模型
              |
        同步引擎与Outbox
              |
          连接器适配层
       /       |       |       \
    Local REST MCP  授权文件夹  导入导出

Agent和前端不能直接访问外部软件、端口、凭据或任意文件夹。

### 7.1 最小接口

    manifest()
    discover()
    connect(grants)
    health()
    pull(cursor)
    planPush(changes)
    push(plan, approval)
    disconnect()

manifest返回：

- 连接器名称和版本。
- 支持的数据类型。
- 读、写、删除和工具能力。
- 所需权限。
- 支持的外部版本。
- 离线和降级能力。

### 7.2 四类连接器

| 类型 | 适用对象 | 默认策略 |
|---|---|---|
| Local REST | Zotero、本地服务 | 固定回环地址、先只读 |
| MCP | 用户科研工具、数据分析服务 | 手动添加、工具逐项授权 |
| 授权文件夹 | Obsidian Vault、Markdown和附件目录 | 用户选择唯一根目录 |
| 导入导出 | 任意软件 | 永远可用 |

### 7.3 用户自有软件接口

允许高级用户连接自己的软件，但：

- 不自动扫描或启动任意可执行文件。
- 本地REST只允许回环地址并拒绝重定向到外网。
- MCP HTTP手动添加；stdio只在高级模式开放。
- stdio使用参数数组启动，禁止拼接Shell命令。
- 工具白名单、输入输出上限、超时和频率限制。
- MCP工具说明和返回内容均视为不可信数据。
- 外部写操作仍需宿主校验和用户确认。

若外部软件需要反向调用论文工作台，另设入站本地网关：

- 默认关闭。
- 只监听回环地址。
- 每个调用方独立Token和权限。
- 不允许访问内部数据库。
- 所有调用进入审计。

## 8. 权限、安全与隐私

权限至少拆分：

    references:read/write/delete
    notes:read/write/delete
    attachments:read
    documents:read/write
    tools:execute
    files:<授权根目录>

规则：

- 首次读取需要明确授权。
- 后台同步有单独开关。
- 写入先生成差异预览。
- 覆盖、删除和工具执行每次确认。
- Agent发起的外部写入必须确认。
- 确认令牌绑定连接器、计划哈希和短有效期。
- 密钥进入Windows Credential Manager等系统凭据库。
- 不在日志中记录正文、附件、Token和完整外部响应。
- 授权文件夹解析真实路径，拒绝路径穿越、目录联接和越界符号链接。
- 不读取或修改Obsidian的配置目录，除非单独授权。
- 不直接访问Zotero SQLite。
- 用户断开时停止同步并撤销运行态权限。

## 9. 最小持久化模型

- integration_connection：连接器、实例、状态、授权和最后同步。
- connector_grant：按数据类型与操作记录权限。
- external_binding：内部对象与外部对象映射。
- sync_checkpoint：游标、版本和时间。
- sync_job：拉取、推送、重试和Outbox。
- sync_conflict：基础、本地、外部版本和解决结果。
- integration_audit：连接、授权、同步、写入和失败记录。

审计默认只保存标识、计数、哈希、耗时和结果，不保存正文与密钥。

## 10. 统一用户体验

设置页提供“资料与连接器”：

- 内置资料中心：始终开启。
- Zotero本地：未发现、待启用、待授权、已连接、离线。
- Zotero云端：未连接、授权中、已连接、授权过期。
- Obsidian Vault：未选择、只读、双向同步、目录失联。
- 文件交换：导入和导出。
- 高级连接：REST和MCP。

用户在文献、笔记、证据和写作界面看到统一数据，不需要进入单独的“外部软件页面”。每条外部资料显示来源、同步状态和“在外部软件打开”可选按钮。

连接状态统一为：

    未发现
    待授权
    连接中
    正常
    离线
    降级
    不兼容
    冲突

失败后不反复弹窗，采用指数退避并保留手动重试。

## 11. 建设顺序

### C0：内置资料中心

- 把现有文献、笔记、图谱、证据和项目记忆统一为一个产品面。
- 补齐Markdown编辑、双链、反链、标签、附件和基础PDF阅读。
- 完成RIS、BibTeX和CSL-JSON导入导出。

### C1：连接器底座

- Connector、Grant、Binding、Checkpoint、Job、Conflict和Audit。
- 文件夹连接器和导入导出。
- 权限网关和差异预览。

### C2：Zotero本地只读

- 发现、版本协商、Collection选择和增量拉取。
- 条目、附件、标签和笔记映射。
- 离线快照。

### C3：Obsidian Vault

- 用户选择目录。
- Markdown、Frontmatter、双链和附件解析。
- 只读挂载、导入副本和打开URI。

### C4：受限双向同步

- 冲突中心。
- Zotero本地写授权。
- Obsidian专用目录写入。
- 删除确认与Outbox。

### C5：云端与开放连接

- Zotero Web API。
- 高级REST/MCP。
- 入站本地网关。
- 可选Obsidian社区插件。

## 12. 完成标准

- 不安装外部软件也能完成论文核心流程。
- 已有Zotero用户能选择Collection并在工作台中使用条目、附件和笔记。
- 已有Obsidian用户能连接授权Vault并使用Markdown、双链和附件。
- 外部离线不阻断写作。
- 外部变化不自动改变正式审批与证据等级。
- 两侧冲突不使用静默最后写入覆盖。
- 用户可撤销权限、断开、清除缓存和导出全部数据。
- 凭据、正文和附件不进入日志。
- 所有写回外部软件的操作可预览、确认和审计。
