## 阻断性问题

### P0-1 作者选题没有成为后端事实

- UI 在 `ui/index.html:4049` 只把作者点选结果写入 `localStorage`。
- 后端在 `backend/application/service/uc_main_orchestration.py:843` 固定使用 `candidates[0]`。
- 后果：用户以为选择了题目2，后续开题、文献、大纲实际围绕题目1运行，审阅确认失去意义。

### P0-2 环6/7的质量 Gate 会批准降级占位稿

- 环6的真实模型调用失败后进入 `backend/executor/ring6_chapter.py:238` 的 Mock，并在 `:261` 返回 `accept=True`。
- 主编排在 `backend/application/service/uc_main_orchestration.py:1070-1074` 无字数、引用、结果覆盖校验，直接标记 `compliant=True`。
- 环7明确允许“LLM 不可用，保留原稿”且 `accept=True`（`backend/executor/ring7/__init__.py:238` 等）。
- 本次被批准稿件只有 960 字，远低于硕士论文要求，且为重复模板句。
- 修复要求：降级结果只能标记 `DEGRADED_DRAFT` 或失败；Gate 必须检查学位字数、章节覆盖、占位文本、引用数量、已批准结果覆盖和非空模型输出。

### P0-3 实验结果账本没有进入默认整稿链路

- `run_ring6` 只检查结果账本是否存在，却没有把账本内容传入 `ExecContext`。
- 结果账本只有分节链路在 `backend/application/service/uc_main_orchestration.py:1990-2014` 被读取。
- 后果：用户完成全部实验协作后，默认“执行当前环节”生成的正文仍不包含实验结果和交叉引用。
- 修复要求：删除整稿/分节两套语义不一致的写作入口，统一使用分节上下文与结果标记协议。

### P0-4 环8阻断后用户无法修复

- UI 只显示“查看后台作业”和再次执行环8。
- 批量正文没有编辑器、引用插入、证据绑定或回退到环6重写入口。
- 重试相同 Job 不会改变“无引用”的输入，因此是确定性失败。
- 修复要求：失败卡必须提供“回到环6修订”“打开正文编辑器”“绑定来源并重新生成”三条明确路径。

## 高优先级问题

### P1-1 研究协议表单异步崩溃

- `ui/index.html:5911` 在 `await apiCreateProtocol(...)` 之后调用 `event.currentTarget.reset()`。
- 异步事件处理完成后 `currentTarget` 已被浏览器置空，产生 `TypeError: Cannot read properties of null (reading 'reset')`。
- 后端协议已保存，但 UI 不关闭、不刷新，用户容易重复提交。

### P1-2 文献结果缺少项目知识库入库与人工整理

- 环3卡片有跳转下载和复制题录，但右侧知识库仍显示 0 篇文献。
- 来源账本能看到 25 条元数据，却没有界面操作去排除明显低相关来源、调整优先级、补全文或标记“核心/背景/方法”。
- 修复要求：检索候选池 → 用户/Agent筛选 → 下载/全文验证 → 知识库登记，应成为同一阶段的显式子状态机。

### P1-3 聊天区阶段摘要持续陈旧

- 阶段条和按钮已推进到环8时，聊天头部仍显示“完成0/10、当前环1”。
- `ui/index.html:5034-5049` 的 `historyBuilt` 短路阻止了摘要更新。
- 后果：用户无法从主要阅读区域判断当前进度，容易误确认或重复执行。

### P1-4 Token预算存在漏记

- 环1~5记录 Token 共 20,385。
- 环6、7确实发起真实模型请求并收到空响应后降级，但 Job 显示 Token 0。
- 后果：失败/降级调用消耗无法计入预算，Token上限和费用治理不能作为硬约束。

### P1-5 长任务轮询过密

- `ui/index.html:5535` 每 900 ms 查询一次 Job。
- 本次 trace 记录约 800 个前端 API 请求，绝大多数为重复状态轮询。
- 修复要求：使用指数退避（1s→2s→5s）或 SSE/WebSocket；页面后台时进一步降频。
