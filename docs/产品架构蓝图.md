# 论文写作智能体产品架构蓝图

> 状态：执行基线（2026-08-24）  
> 适用范围：本地优先、单作者的本/硕/博论文写作工作台  
> 产品原则：智能体负责组织、生成、校验和解释；作者负责证据选择、学术判断与最终确认。

## 1. 产品定义

本产品不是“一键生成论文”的聊天框，而是一套把论文研究与写作拆成可执行工作单元的工作台。每个论文任务拥有独立的会话、知识库、十阶段状态、产物版本和审计记录。任何阶段都必须产生可检查的结构化产物，自动验收通过后仍需作者确认，才允许推进。

核心价值按优先级排列：

1. **证据可追溯**：每个事实性主张能回到来源、页码或数据位置。
2. **过程可恢复**：阶段、版本、退回原因和人工决定可以重放与审计。
3. **写作可编辑**：大纲、章节和引用是独立对象，不是一次性的大段模型输出。
4. **失败可见**：模型、检索或校验不可用时明确失败，不把占位内容伪装为完成品。
5. **交付可验证**：导出前检查引用、材料、结构、格式和待办项，最终确认后才标记完成。

## 2. 目标用户与主流程

### 2.1 目标用户

- 本科生：需要明确的流程引导、基础文献组织和学校模板适配。
- 硕士生：需要系统综述、研究问题收敛、方法与实验论证、引用审计。
- 博士生：需要更深的证据网络、创新主张管理、多轮章节评审和长期版本治理。

导师、共同作者和机构管理员属于后续协作范围，不进入当前单机版的权限模型。

### 2.2 十阶段工作流

| 环 | 阶段 | 核心输入 | 结构化产物 | 自动验收 | 人工决定 |
|---|---|---|---|---|---|
| 1 | 选题 | 学科、学位、兴趣、约束 | 候选题目、研究问题、创新假设 | 完整性、范围、可研究性 | 选择或改题 |
| 2 | 开题评审 | 选题、初步检索结果 | 新颖度与可行性报告 | 泛化、重复、资源风险 | 通过或退回环1 |
| 3 | 文献调研 | 检索式、来源范围、时间范围 | 文献池、去重结果、可靠度 | 非空、标识符、来源记录 | 纳入、排除、补检索 |
| 4 | 综述评审 | 文献池、研究问题 | 主题簇、争议、空白、证据矩阵 | 引用深度、证据覆盖 | 通过或退回环3 |
| 5 | 大纲 | 研究问题、证据矩阵 | 章/节树、论点、证据槽位 | 层级、逻辑、覆盖 | 锁定或调整结构 |
| 6 | 撰写 | 章节任务、证据槽位、笔记 | 分节草稿、主张列表、引用占位 | 字数、证据绑定、禁编造 | 逐节接受或重写 |
| 7 | 润色 | 已接受草稿、术语表 | 修订稿、变更摘要 | 引用和数字指纹保留 | 接受修订或回退 |
| 8 | 引用校验 | 主张、引用、文献元数据 | 引用审计报告、风险项 | 无来源/错配/伪引检查 | 修复或接受风险 |
| 9 | 排版 | 稿件、模板、学校规则 | docx、版式报告 | 标题、页眉页脚、目录等 | 修复或进入定稿 |
| 10 | 定稿 | 全部产物与审计结果 | 交付清单、最终文件 | 材料齐全、阻断项清零 | 最终确认 |

每一环的协议固定为：

```text
NOT_STARTED / FALLBACK
        │ execute
        ▼
自动验收失败 ───────────────► FALLBACK
        │ 自动验收通过
        ▼
WAITING_APPROVAL
        │ 作者确认
        ▼
下一环 NOT_STARTED；环10确认后 PASSED
```

执行接口只提交产物，不得推进；确认接口只确认当前待确认产物，不得生成产物。这个边界同时适用于前端、HTTP API、演示脚本和后台任务。

## 3. 产品信息架构

### 3.1 顶层对象

- **论文任务 Task**：题目、学位、学科、检索范围、学校模板、当前阶段。
- **会话 Session**：作者与智能体围绕该论文产生的消息、指令和决定。
- **知识库 Knowledge Base**：该任务的文献、附件、笔记、摘录、图谱和索引。
- **阶段运行 Ring Run**：一次执行的输入快照、输出、自动验收和运行日志。
- **产物 Artifact**：候选题、评审报告、文献池、大纲、章节、审计报告或文档。
- **人工决定 Approval**：接受、拒绝、原因、时间和产物版本。

Task、Session 与 Knowledge Base 在当前产品中是 1:1:1。删除任务时必须在同一事务边界内删除会话索引和知识库；文档文件优先进入可恢复回收区，永久删除属于单独动作。

### 3.2 写作对象

环6不能长期停留在“一次模型调用返回整篇论文”的模式。目标写作模型如下：

```text
OutlineNode
  └─ SectionDraft（可多版本）
       ├─ Claim（主张）
       │    └─ EvidenceLink（证据链接）
       ├─ CitationOccurrence（引用出现位置）
       └─ Revision（修改记录）
```

每个 SectionDraft 单独生成、保存、验收和重写。章节只是已接受分节的有序聚合。这样可以控制上下文、成本和失败范围，也能让作者编辑具体段落而不是反复生成整篇文本。

### 3.3 证据对象

文献元数据与“文献是否支撑某个主张”是两件事，必须分开存储：

- `SourceRecord`：标题、作者、年份、DOI/URL、来源数据库、抓取时间、可靠度。
- `EvidenceExcerpt`：原文摘录、页码/章节/段落定位、文件哈希、提取方式。
- `Claim`：草稿中的事实性或方法性主张。
- `EvidenceLink`：Claim 与 EvidenceExcerpt 的支撑、反驳或背景关系，以及人工确认状态。
- `CitationOccurrence`：正文中的引用位置和所用格式。

没有 EvidenceExcerpt 的引用最多标记为“元数据已核验”，不能显示成“内容已证实”。

## 4. 系统架构

当前阶段采用模块化单体，不拆微服务：

```text
Browser UI
   │ REST / multipart / file download
FastAPI Application
   ├─ Writer Console（用例编排、权限边界）
   ├─ FSM（十环状态、确认、回退）
   ├─ Executors（模型、检索、校验）
   ├─ Knowledge（文件、笔记、RAG、图谱）
   ├─ Writing（目标：大纲/分节/主张/版本）
   ├─ Citation（目标：证据账本与引用审计）
   └─ DOCX（模板解析、渲染、版式检查）
        │
SQLite + local file storage
        │
Model API / literature APIs / local embedding model
```

采用模块化单体的原因：当前是本地单作者应用，事务一致性、调试和数据可恢复性比独立扩缩容重要。只有在出现多人协作、长任务队列或独立检索吞吐需求后，才拆分工作进程或服务。

### 4.1 边界规则

- Controller 只做输入解析、会话校验和 Result 转换。
- Application Service 决定用例顺序，不包含模型提示词细节。
- FSM 只管理阶段与确认，不理解具体论文内容。
- Executor 生成或校验单环产物，不直接修改 FSM。
- Repository 负责持久化；跨任务数据查询必须显式带 task/session 范围。
- UI 不推断阶段成功；只依据后端返回的 `phase_state`、`can_execute` 和 `can_confirm`。

### 4.2 运行状态

除阶段状态外，每次执行还需要独立运行状态：`QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELLED`。长时模型调用、全文解析和文献检索应进入后台作业，并提供取消、超时、重试与可观测进度。阶段状态不能拿来代替作业状态。

## 5. 可信生成策略

### 5.1 默认失败策略

- 正式模式下模型未配置、超时或结构化输出失败：该次执行失败并保留原因。
- Mock 只允许在测试或明确的离线演示模式开启，UI 必须显示“演示数据”。
- 文献检索为空：环3失败；后续写作不得临时伪造文献池。
- 引用为空或无法映射到文献池：环8失败。
- 定稿材料缺失：环10失败。

### 5.2 生成前上下文

分节生成只接收：当前研究问题、当前节任务、已锁定上文摘要、术语表、允许使用的 EvidenceLink、篇幅与文风约束。模型不得看到整个无筛选知识库，也不得自行引入池外文献。

### 5.3 生成后验收

自动验收分三层：

1. **结构层**：JSON schema、必填字段、章节层级、引用标记合法性。
2. **证据层**：引用存在、主张可映射、数字与原文一致、来源可靠度。
3. **写作层**：跑题、重复、术语漂移、段落逻辑、学位层次要求。

自动验收只能决定“是否允许作者确认”，不能代替作者确认。

## 6. API 契约

推荐保留的工作台命令：

```text
POST /api/v1/console/tasks
GET  /api/v1/console/tasks/{task_id}/progress
POST /api/v1/console/tasks/{task_id}/rings/{ring_no}/execute
POST /api/v1/console/tasks/{task_id}/rings/{ring_no}/confirm
POST /api/v1/console/tasks/{task_id}/rings/{ring_no}/retry
POST /api/v1/console/tasks/{task_id}/rollback
```

当前各环仍有具名执行路径，可在保持兼容的同时逐步收敛到统一 `execute` 命令。确认请求至少包含 `artifact_version` 和幂等键，防止用户在旧页面确认已经被重写的产物。

错误信封需要稳定区分：输入错误、非法状态、外部服务失败、自动验收失败和系统错误。HTTP 状态码应与业务信封一致；正式版不再把所有失败包装成 HTTP 200。

## 7. 数据与版本治理

### 7.1 本地持久化

SQLite 负责结构化元数据，本地文件目录保存 PDF、docx、抽取文本和索引。所有数据库记录中的文件路径使用任务作用域内的相对标识，不把任意绝对路径暴露给前端。

### 7.2 版本规则

- 产物内容不可原地覆盖；新执行生成新版本。
- Approval 必须指向确定的产物版本。
- 回退只改变活动版本指针，不删除后续版本。
- 文献文件以内容哈希去重；元数据修订保留来源与时间。
- 最终导出记录输入版本集合、模板版本和校验报告哈希。

### 7.3 备份与迁移

正式本地版至少提供“导出任务包”和“导入任务包”。任务包包含数据库切片、知识库文件、产物和清单哈希；密钥与机器级配置不进入任务包。

## 8. 安全与隐私

当前明确定位为本机单用户服务，默认只监听 `127.0.0.1`。在提供局域网或公网访问前，必须完成：

- 用户认证、任务所有权与文件下载授权。
- CORS 精确来源，不允许生产环境使用 `*`。
- 上传文件类型、大小、压缩炸弹和路径穿越防护。
- API 密钥只从环境或系统密钥库读取，日志中脱敏。
- 外发模型请求预览：让作者知道哪些正文、摘录或个人数据将被发送。
- 数据保留、回收站和彻底删除策略。

## 9. 体验原则

界面细节以仓库根目录 `DESIGN.md` 为准。产品层必须满足：

- 首屏明确显示当前任务、当前阶段、执行状态、验收状态和下一步。
- 长任务在原位置显示进度、取消和失败原因，不使用无信息的全局转圈。
- 刷新或重启后恢复待确认闸门，不能把已执行产物重新当作未开始。
- 任何模型生成内容都能定位到输入来源、运行时间和模型配置。
- 作者可直接编辑大纲和分节；聊天指令是辅助入口，不是唯一入口。

## 10. 可观测性与质量

每次执行记录：`task_id`、`ring_no`、`run_id`、产物版本、模型/检索源、耗时、重试、token/费用、验收规则和失败类别。日志不得写入密钥、完整上传文件或未经用户选择的正文全文。

测试分层：

- 单元测试：FSM、验收器、引用解析、文档规则。
- 应用闭环：用确定性替身验证十环协议和回退。
- 合同测试：外部模型和文献服务的响应 schema。
- 真实冒烟：显式启用、受预算限制，不进入普通 CI。
- 浏览器流程：创建任务、执行、刷新恢复闸门、确认、回退、导出。

## 11. 建设路线与完成标准

### 已落地：可信闭环基础

- 十环执行与确认分离；所有环都必须经过 `WAITING_APPROVAL`。
- 跨环执行被拒绝，最终确认后进度为 100%。
- 正式模式默认禁止模型失败后静默 Mock。
- 空引用不通过环8，缺材料不通过环10。
- docx 只能在进入环9后生成，并优先使用环7润色稿。
- 前端刷新可恢复待确认闸门；闭环测试覆盖 HTTP 与应用服务。

### P0：可真实使用的写作核心

- 大纲节点、分节草稿、版本和作者编辑 API。
- 环6按节生成与逐节验收，停止“一次生成整篇”。
- 自动保存、版本对比、局部重写和撤销。
- 证据账本最小模型：Source、Excerpt、Claim、EvidenceLink。

验收：作者可从已确认大纲逐节写完一章；每个事实性主张能看到证据状态；重写一节不影响其他章节。

### P1：研究与引用闭环

- 检索式工作台、去重、纳入/排除理由、全文导入。
- PDF 摘录页码定位与证据卡。
- 引用样式、参考文献表、正文引用双向定位。
- 环8按“元数据核验/内容支撑/人工确认”分级报告。

验收：随机抽取任意正文引用，可回到文献记录与原文位置；不存在池外或无法解释的引用。

### P2：学校模板与交付

- 模板映射向导、目录/页码/页眉页脚/图表题注规则。
- docx 预览、规则定位与一键回到源章节修订。
- 任务包备份恢复和最终交付清单。

验收：使用目标学校模板导出的文档通过已配置的自动版式规则，所有阻断项清零后才能最终确认。

### P3：产品化

- 后台作业、取消与恢复、费用预算和运行历史。
- UI 拆分为可测试组件，补齐键盘导航与响应式降级。
- 桌面打包、升级与数据迁移。
- 若进入多人场景，再加入认证、角色、评论和导师审批。

验收：断网、模型超时、应用重启和失败重试不会破坏任务数据或错误推进阶段；发布构建具有可重复安装与升级路径。

## 12. 当前不应宣称的能力

在 P0/P1 完成前，不应把项目描述为“可以稳定生成符合本硕博字数要求的完整论文”。现有环6仍是整批草稿生成器，真实字数、分节编辑和证据逐条绑定尚未达到可交付标准。外部文献 API 的元数据命中也不等于全文事实已核验。

对外准确定位应是：**已具备可信十阶段控制流、文献与知识库基础、基础生成/校验和 docx 管线的工程化原型，正在建设可真实写作的分节与证据核心。**
