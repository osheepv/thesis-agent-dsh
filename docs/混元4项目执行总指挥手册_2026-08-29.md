## 3. 产品目标

### 3.1 一句话定义

构建一个面向本科、硕士和博士论文的全流程智能体工作台：用户给出论文方向后，智能体逐阶段引导用户完成选题、开题、文献、综述、研究或实验、写作、润色、引用核验、排版和交付；用户主要负责提供真实材料、完成无法由软件代替的实验或调查、评审每阶段产物并决定是否进入下一阶段。

### 3.2 最终理想体验

用户不需要每天重新向模型解释项目。一个论文项目可能持续数周或数月，系统必须持久记住：

- 当前论文任务和当前环节。
- 已确认、待确认、被退回和已过期的产物版本。
- 已纳入、已排除、待核验和有风险的文献。
- 研究问题、作者决定、导师意见、术语和写作风格。
- 研究协议、实验手册、材料清单、原始数据、代码、日志和结果账本。
- 每个章节、分节、论断、证据和引用之间的关系。
- 未完成作业、失败原因、重试入口、Token和费用。
- 用户上次停留的任务、工作台页签和编辑位置。

用户再次打开应用时，系统应清楚回答三个问题：

1. 上次停在哪里？
2. 已经完成和批准了什么？
3. 下一项唯一安全动作是什么？

系统不能因为刷新、断网、后端重启或聊天额度耗尽而丢失正式状态，也不能无故重跑已经计费完成的模型任务。

### 3.3 “成稿令人满意”的工程含义

产品目标不是承诺机器生成“绝对完美论文”，而是交付一份作者可审查、可修改、格式规范、引用完整、交叉引用有效、证据可追溯、风险透明的成稿。学术判断和最终责任仍属于作者。

正式交付至少应满足：

- 章节结构与学校模板一致。
- 正文、图、表、公式、题注、目录和编号可复检。
- 文内引用与参考文献一一对应。
- 引用不是凭空生成；元数据、全文摘录和作者复核等级明确区分。
- 事实性论断能定位到证据或被明确标记为待核验。
- 研究或实验结果来源真实，不能由模型编造。
- 交叉引用在Word中是有效字段或等效的可维护引用，不只是看起来相同的文本。
- 最终文件附带质量审计和未解决风险清单。

## 4. 不可更改的产品边界

以下规则属于项目宪法。混元4不能为了实现方便而修改。

### 4.1 不是“一键生成论文”

产品是一个可审计的论文研究与写作工作台，不是输入题目后自动输出全文的聊天框。前端不得新增“跳过全部审批”“一键完成十环”“自动通过全部结果”等入口。

### 4.2 十环确定性状态机是外轨

正式流程固定为：

    生成结构化产物
    → 自动验收
    → WAITING_APPROVAL
    → 作者评审和明确确认
    → 下一环

执行接口只能生成和提交产物，不能推进环节。确认接口只能确认当前待审版本，不能顺带生成内容。任何环都不得跳过人工确认。

### 4.3 Agent只能在有界内轨工作

智能体可以在某一环内部规划、读取证据、调用只读工具和提出候选修改，但必须受到：

- 最大轮数。
- 最大工具调用数。
- 最大观测长度。
- Token和费用预算。
- 工具白名单。
- 宿主端校验。

Agent不能拥有通用SQL、任意文件写入、原地覆盖正文、直接批准产物或推进FSM的工具。Agent输出必须由宿主验证，并创建新版本后等待作者审批。

### 4.4 正式模式不静默降级

DeepSeek失败、超时、返回空内容、JSON截断、材料不足或文献不足时，系统必须明确失败或进入可恢复状态。不得在正式模式静默切换到Mock，再把Mock内容当成真实结果。

### 4.5 当前只支持DeepSeek

当前产品决策是只支持DeepSeek OpenAI兼容接口。不要提前建设OpenAI、Claude、混元或通用多供应商抽象。模型供应商扩展属于未来阶段，只有Codex重新派发后才能开始。

### 4.6 学术证据必须诚实分级

- 搜到题录或DOI，只能说明元数据命中。
- 下载到全文，不等于其中内容已经支撑某个论断。
- 抽取到相关原文，也不等于作者已经复核。
- 用户上传文件不能自动升级为“已核验文献”。
- 非literature类型的文件不能混入文献池。
- 摘录、页码、定位信息和作者审批必须分别记录。
- 不得伪造文献、DOI、页码、实验数据或引用关系。

### 4.7 版本不可被原地覆盖

正式Artifact、SectionDraft、研究协议、论证图、结果账本和项目记忆的修订必须形成新版本。Approval必须指向一个确定版本；回退可以改变活动版本，但不能删除历史。

### 4.8 工作区状态不是业务真相

最后任务、活动页签、展开项和编辑锚点只描述用户界面位置。它们不能决定某一环是否完成，不能替代FSM、产物账本、审批记录或Job状态。

### 4.9 恢复不能产生副作用

恢复页面或点击“继续上次论文”只能导航、展示和聚焦，不得：

- 自动执行当前环。
- 自动确认待审批产物。
- 自动重跑失败或已完成Job。
- 自动调用真实模型。
- 自动覆盖草稿或正式版本。

## 5. 用户全流程

| 环 | 阶段 | 智能体主要工作 | 用户主要工作 | 关键产物 |
|---|---|---|---|---|
| 1 | 选题 | 收集约束、生成候选题、研究问题和创新假设 | 选择、修改或补充现实约束 | 已确认选题 |
| 2 | 开题评审 | 评估新颖度、可行性、资源和伦理风险 | 决定通过或退回选题 | 开题可行性报告 |
| 3 | 文献调研 | 生成检索式、主动检索、下载、去重、登记、排序 | 上传重要文献并决定纳入或排除 | 可追溯文献池 |
| 4 | 综述评审 | 聚类主题、争议、研究空白和证据矩阵 | 检查综述是否准确、是否需要补检索 | 综述与证据矩阵 |
| 5 | 大纲 | 生成章/节树、论点和证据槽位 | 调整并锁定结构 | 已批准大纲 |
| 6 | 撰写 | 按节读取最小必要上下文，生成和修订草稿 | 逐节接受、驳回或提供反馈 | 分节版本和章节稿 |
| 7 | 润色 | 改善语言、连贯性和术语一致性，保留事实指纹 | 审查改动是否改变原意 | 修订稿与变更摘要 |
| 8 | 引用校验 | 检查缺引、错引、伪引、池外引用和元数据 | 修复或明确接受剩余风险 | 引用审计报告 |
| 9 | 排版 | 应用学校模板，生成docx并检查版式 | 提供模板、查看最终排版 | docx与格式报告 |
| 10 | 定稿 | 汇总交付清单、质量审计和最终文件 | 最终确认 | 成稿与审计包 |

研究和实验不是额外的“聊天建议”，而是贯穿环2至环6的受控工作流。智能体可以提出实验建议并共同生成实验项目手册，但用户必须准备真实材料、执行实验并提交原始结果。系统只做归纳、登记、分析建议和证据绑定，不得生成虚假结果。

## 6. 当前技术架构

### 6.1 总体形态

当前采用本地优先的模块化单体，不拆微服务。理由是当前阶段最重要的是事务一致性、调试、数据恢复和单作者体验，而不是独立扩缩容。

主要技术：

- Python 3.12及以上。
- FastAPI后端。
- 原生HTML、CSS和JavaScript桌面式Web UI。
- 当前以多个SQLite持久层支撑任务、FSM、产物、证据、研究、写作和Job。
- DeepSeek OpenAI兼容客户端。
- docxtpl及项目自有DOCX生成、模板解析、校验和交叉引用模块。
- pytest测试。

### 6.2 核心模块地图

| 领域 | 主要路径 | 职责 |
|---|---|---|
| HTTP入口 | backend/application/controller/writer_console.py | 控制台API、身份边界和结果信封 |
| 主编排 | backend/application/service/uc_main_orchestration.py | 连接任务、FSM、产物、证据、研究、写作和Job |
| 工作流契约 | backend/common/workflow_contracts.py | 十环输入、产物与约束 |
| FSM | backend/fsm/orchestrator/ | 环状态、执行、确认和回退 |
| 环执行器 | backend/executor/ | 环1至环10执行逻辑 |
| 有界Agent | backend/common/agent_loop.py | 轮数、工具和预算受限的Agent Loop |
| 项目记忆 | backend/common/project_memory.py | 研究问题、决定、术语和风格的版本化长期上下文 |

### 6.3 状态真相源

模型上下文、浏览器内存和聊天历史都不是真相源。正式状态必须来自：

- Task：项目身份和基本约束。
- FSM：当前环及阶段状态。
- Artifact Registry：正式产物、版本、审批和依赖。
- Evidence Ledger：论断和证据关系。
- Research Registry：研究协议、论证图、材料和结果。
- Writing Registry：分节草稿和版本。
- Job Registry：长任务状态、预算、租约和使用量。
- Workspace State：仅保存用户界面位置。
- 未来Draft Store：仅保存未提交编辑，不得替代正式产物。

- 普通CI离线运行，不访问网络，不需要API Key。
- 正例、反例和边界例齐全。
- 失败报告指出具体case和原因，不只给总分。
- 不复制受版权保护的长篇全文。
- 规则评测不冒充真实模型质量结论。
- 真实模型评测另设显式execute路径和硬预算。

### H4-004：审批身份防伪造

目标是取消审批接口对请求体actor字段的信任。

需要审计的路径：

- 证据摘录审批。
- 单节审批。
- 批量分节审批。
- 论证图审批。
- 研究协议审批。
- 结果账本审批。

规则：

- actor统一来自request.state.principal.username。
- 本地关闭认证时才回退固定author。
- 请求体传入actor必须被忽略。
- 不顺带重做整个RBAC。

DoD：

- 伪造actor不会进入审计记录。
- viewer不能修改或审批。
- reviewer和owner的真实身份正确记录。
- 六条路径都有API测试。

### H4-005：HTTP状态码和异常脱敏

目标：

- 不再把所有错误包装成HTTP 200。
- 不再把未知异常的str(exc)直接发给客户端。

保留Result信封，统一映射：

- 输入错误：400或422。
- 未认证：401。
- 无权限：403。
- 不存在：404。
- 状态、版本或revision冲突：409。
- 上游服务错误：502或504。
- 未知错误：500。

客户端只返回稳定错误码、简短消息和traceId；完整异常只进入服务端脱敏日志。

DoD：

- 返回体不含绝对路径、API Key、完整请求正文或堆栈。
- UI面对4xx和5xx仍能显示业务消息。
- 增加错误契约和敏感信息测试。

### H4-006：Token与费用调用前预估

已有Job预算和实际用量，本阶段只补调用前预估、任务累计和诚实的单价状态。

DoD：

- 入队前显示预计输入Token、最大输出、预计费用区间和预算余量。
- 单价未配置时显示“费用不可观测”，不能显示虚假的0元。
- 任务级累计Token和费用可查询。
- Job结束后可比较预估和实际。
- 预估接口不调用模型。

### H4-007：Job UI模块化与SSE

先拆模块，再加SSE，不引入React、Vite或新前端框架。

第一小步：

- 从ui/js/app.js提取Job相关函数到ui/js/components/jobs.js。
- 通过小型runtime接口访问API、toast和当前任务。
- 保持现有经典script加载方式和视觉。
- 删除迁移后的旧函数，不保留两套实现。

第二小步：

- 增加任务作用域的SSE进度。
- 事件只含状态、环节、Token、时间和简短消息，不含章节正文。
- 支持事件序号、断线重连和轮询降级。
- 保持认证、租户隔离、取消和重试语义。

DoD：

- 轮询与SSE结果一致。
- 断线后恢复且不重复产生副作用。
- 浏览器控制台无错误。
- 不依赖Redis即可完成本地单机版本。

### H4-008：跨存储启动对账

当前consistency_status主要检查Artifact Outbox，不能代表任务、FSM、分节、Job和知识库的完整一致性。

第一版只做只读对账器，例如：

    backend/application/service/recovery_reconciler.py

检查：

- Task存在但FSM缺失。
- FSM当前环与已批准产物矛盾。
- 待审批版本不存在。
- SectionDraft引用的上游产物缺失或过期。
- Job已成功但目标产物缺失。
- 研究结果指向不存在的知识库文件。
- 删除任务后仍有跨库记录。
- Artifact Outbox未投影。

DoD：

- 发现问题时返回NEEDS_REPAIR。
- 阻止继续确认下一环。
- 恢复摘要返回稳定问题代码。
- 第一版不自动删除、不猜测修复。
- 故障注入只使用临时目录。

自动修复生产数据、跨库破坏性迁移和永久文件删除必须由Codex另行设计，不授权混元4自由实现。

### H4-009：事务边界与Alembic迁移

这是高风险阶段。混元4第一轮只允许做清点、ADR、迁移夹具和验收矩阵：

- 列出各Registry的表、SQLite文件和提交边界。
- 设计统一Unit of Work或单SQLite方案。
- 建立旧数据备份、导入、失败回滚和重复迁移测试。
- 建立Alembic基线设计。

Codex审核设计后才可实施：

- 统一SQLite文件或事务边界。
- Alembic迁移。
- 旧多库数据迁移。
- 删除补偿。

PostgreSQL仍是后续可选部署，不是当前默认，不得与SQLite收敛同时推进。

停止条件：

- 没有可恢复备份。
- 迁移失败可能损坏用户现有论文。
- 准备直接删除旧数据库。
- 准备同时迁移PostgreSQL。

### H4-010：学校模板与正式交付

按小阶段建设：

1. 图片、表格、题注和连续编号。
2. 正文原生交叉引用。
3. LaTeX或MathML到Word OMML公式。
4. 学校模板样式差异诊断。
5. DOCX和PDF导出复检。

相关模块：

    backend/thesis_docx/cross_reference.py
    backend/thesis_docx/generator/
    backend/thesis_docx/validator/
    backend/thesis_docx/parser/
    backend/thesis_docx/service/

每一小步都要生成可打开的DOCX fixture，验证唯一书签、字段引用、题注编号和round-trip，不能只检查XML字符串存在。

### H4-011：有界Agent扩展到更多环

只能在H4-003评测集建立后，一环一环扩展：

- 环1：候选选题与约束检查。
- 环4：证据矩阵和研究空白。
- 环5：大纲与证据槽位。
- 环7：变更建议和事实指纹。
- 环8：引用问题定位和修复建议。

硬边界：

- FSM仍是确定性外轨。
- 每个Agent有固定轮数、工具数和Token预算。
- 工具默认只读。
- Agent只提出候选内容或变更建议。
- 宿主校验并创建新版本。
- 必须作者审批。
- 禁止通用写库、任意文件写入和原地覆盖正文。

每增加一环，都需要单独的离线测试、故障测试、提示词版本和受控真实模型验收，不能一次性扩展五环。

### H4-012：真实模型、压力测试和首个预览版本

只有学术评测阈值冻结后才能执行：

1. 使用硬预算重跑本科代表任务。
2. 对照上次报告，证明文献相关性和证据覆盖改善。
3. 再运行硕士代表任务。
4. 最后运行博士长任务和故障恢复矩阵。
5. 通过后准备首个可下载预览版本。

真实脚本：

    scripts/real_full_flow_acceptance.py
    scripts/real_agent_loop_acceptance.py

普通测试和CI永远不得调用真实DeepSeek。真实脚本默认只做预检，只有项目所有者明确授权并加execute参数后才能产生费用。

故障矩阵至少覆盖：

- 每一环执行前和执行后强杀进程。
- WAITING_APPROVAL时重启。
- 分节生成中断和检查点恢复。
- Job领取后Worker重启。
- DeepSeek空响应、超时、JSON截断和预算耗尽。
- 断网后恢复。
- 重复提交和幂等复用。
- 已计费产物不重复生成。

## 14. 总体停止规则

混元4遇到以下任一情况必须停止并把证据交回Codex：

- 需要改变产品目标、十环顺序或每环人工审批。
- 需要增加DeepSeek以外的模型Provider。
- 需要真实DeepSeek调用或产生费用。
- 需要数据库破坏性迁移或删除旧数据。
- 需要删除用户文件、外部报告或Git历史。
- 需要处理API Key、GitHub Token或登录验证码。
- 发现已有用户改动与任务重叠，无法安全合并。
- 需要修改任务卡未列出的核心模块。
- 需要修改.github/workflows。
- 两轮修复后仍无法通过同一测试门禁。
- 只能通过降低质量标准、静默Mock、伪造文献或伪造测试结果来通过验收。
- 当前HEAD与origin/main发生不明分叉。
- GitHub push或CI结果与本地不一致且原因未知。

停止不是失败。保留可复现证据、保护现场并请求决策，比擅自修复高风险问题更重要。
