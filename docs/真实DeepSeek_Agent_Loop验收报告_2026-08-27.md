# 真实DeepSeek Agent Loop验收报告

## 结论

2026-08-27，环6写作计划Agent在`deepseek-v4-flash`上完成一次有上限的真实供应商验收，结果为**通过**。

验收只生成两章写作计划，不生成论文正文。模型只能使用已注册的只读工具，整次调用受轮数、工具数、观测长度和Token预算共同限制。

工具轨迹由`read_approved_context`、`search_sources`、`check_citation`和`check_plan_structure`组成。其中模型产生了重复只读调用，循环使用首次观测的缓存结果响应，没有重复执行底层工具。

## 验收过程发现与修复

1. **4轮不足以收敛**：DeepSeek完成读取、检索和校验后没有剩余轮次输出最终计划。默认上限调整为6轮，仍不允许无上限循环。
2. **8次工具上限偏紧**：两章样例在完整校验链中超过8次，最终上限调整为12次。
3. **重复只读调用**：完全相同的第二次调用改为缓存观测，第三次仍会被视为持续重复并拒绝。
4. **JSON前的说明文字**：模型完成最终计划后曾在JSON前输出一句说明。解析器现可提取首个合法JSON对象，但Pydantic结构、章节覆盖和引文核验门禁不变。
5. **池内不等于已核验**：程序现在记录`check_citation`成功集合；即使`[L序号]`存在于文献池，未实际调用核验也会失败。

前四次调用都由边界或校验器明确拒绝，没有静默降级、没有越过工具白名单，也没有继续生成论文正文。

## 可重复命令

```bash
# 只预检，不调用模型
python scripts/real_agent_loop_acceptance.py

# 显式执行一次真实有界验收
python scripts/real_agent_loop_acceptance.py --execute
```

脚本的脱敏JSON运行报告默认保存在`output/acceptance/`，该目录已被Git忽略。报告不包含API Key、论文正文或完整供应商响应。

## 剩余风险

- 本次只验收两章计划，不代表硕士/博士长篇写作已通过。
- 6轮与11次工具已接近默认上限；更多章节应考虑按章拆分计划，而不是继续放大单次循环。
- 当前费用字段依赖环境单价；未配置时只能准确报告Token，不能报告金额。
