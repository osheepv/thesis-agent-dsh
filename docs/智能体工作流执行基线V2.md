# 智能体论文写作全流程执行基线 V2

> 状态：P0 工程基线  
> 原则：十环负责作者可理解的宏观进度；环内任务图负责检索、实验、写作和审查的真实循环。

## 1. 本轮冻结的架构决定

1. 保留现有十环 API 和 FSM 编号，不另造一套互相冲突的阶段编号。
2. 每一环都必须执行“生成产物 → 自动验收 → 作者审批”；作者审批指向确定的产物版本。
3. 研究设计、实验/研究实施和结果血缘纳入环5、环6的强制内部工作流。
4. 子 Agent 不通过自由聊天传递事实，只通过版本化结构产物传递。
5. 新上游版本获批后，旧版本的下游产物递归标记为 `STALE`，但不删除历史。
6. 向量索引只是检索视图；文献、原文摘录、实验文件和结果记录才是事实源。

## 2. 双层编排

```text
十环 FSM
  └─ 当前环 Task DAG
       ├─ 专业 Agent / 确定性工具
       ├─ 版本化 Artifact
       ├─ 自动 Gate
       └─ 作者 Approval
```

十环的单一机器可读定义位于 `backend/common/workflow_contracts.py`。其中
`required_artifact_kinds` 是产品完成条件，`implemented_artifact_kinds` 是当前真实能力；
二者差集必须显示为建设缺口，禁止把未实现能力伪装成已完成。

## 3. 环5、环6的研究实施协议

环5至少产出：

- `RESEARCH_PROTOCOL`：研究问题、假设、方法、变量、程序、分析方案、伦理要求；
- `ARGUMENT_MAP`：论文主张、反主张、证据槽位和章节关系；
- `OUTLINE`：可逐节执行的详细大纲。

环6按论文类型路由：

- 实证/系统类：等待作者提交实验材料、原始数据、代码与日志，登记 `EXPERIMENT_RUN` 和 `RESULT_LEDGER`；
- 理论类：登记证明、推导或模型验证材料；
- 质性类：登记访谈、编码、案例和伦理材料；
- 综述类：登记检索、筛选、质量评估和综合结果。

没有可追溯研究产物时，系统不得生成确定性实验或结果结论。

## 4. 产物协议

`backend/artifacts/` 已实现最小持久化底座：

- 内容不可原地覆盖，只能新增版本；
- 只能依赖同任务中已批准且仍有效的上游产物；
- 自动验收通过后才能等待作者审批；
- 新版本批准后才替代旧版本并递归使下游过期；
- 每次调用保存 `ContextManifest`，记录提示词、模型、输入产物、证据和 Token。

主编排器现通过事务 Outbox 接入该协议：用户审批与产物事件随 FSM/Gate 原子提交，
随后幂等投影到产物仓库；进程中断时，`progress` 与产物列表查询会重放待处理事件。
`GET /api/v1/console/tasks/{task_id}/artifacts` 返回全部版本、依赖和失效状态。

## 5. 证据账本（已实现）

`backend/evidence/` 已实现四层可信链：

- `SourceRecord`：题录、DOI/URL、来源渠道和核验状态；环3批准后自动幂等登记；
- `EvidenceExcerpt`：原文摘录及页码、章节或字符偏移；必须由作者复核；
- `Claim`：正文中的事实、数字、方法、解释或贡献论断；
- `EvidenceLink`：明确记录支持、反驳、背景或方法关系。

未经批准的摘录不能与论断建立链接；摘录后来被驳回时，审计会立即重新阻断相关
论断。`evidence-audit` 只有在至少存在一个论断且全部有有效支持、无反证时才允许发布。

## 6. 研究实施与结果血缘（已实现）

研究协议作为环5的 `RESEARCH_PROTOCOL` 版本化产物单独审批。实验/研究运行按
`PLANNED → MATERIALS_READY → RUNNING → COMPLETED` 状态机推进；完成时强制登记
原始数据或日志，并由用户确认材料真实。每条结果记录必须指向该次运行已经登记的
文件，保存计算方法，并再次由用户核验。

实证、质性、混合和系统构建类研究必须生成并批准 `RESULT_LEDGER`，环6才能开始
生成初稿。环6草稿同时依赖大纲和结果账本；协议或结果账本升级时，下游草稿会过期。

## 7. 论证图（已实现）

环5的 `ARGUMENT_MAP` 明确保存研究问题、核心论断、子论断、反论断、局限、章节位置、
父子关系和证据需求。自动 Gate 会拒绝重复键、不存在的父节点、自依赖、循环依赖以及
没有核心论断的图。批准后每个论断按稳定 `source_key` 幂等登记到证据账本。

大纲在启用论证图的任务中必须等待其批准，并同时依赖综述、研究协议与论证图；新论证
版本获批会自动使旧大纲及其下游产物过期。

## 8. 分节写作与引用审计（已实现后端基线）

环6可按大纲 `section_id` 逐节执行。每次模型调用只接收该节论断、已批准原文摘录、
经用户核验的结果以及必要上游产物 ID；未经支持的事实论断或未解决的反证会在调用前
阻断。模型若返回上下文外证据/结果 ID，自动 Gate 会拒绝该版本。

每节独立版本化并单独保存作者审批审计。大纲的所有目标分节都有有效批准版本后，系统
才允许汇编环6正式产物。环7事实指纹会保护 `[EVD-*]` 和 `[RES-*]` 标记；环8将其
核对到证据、来源、论断和结果账本，生成稳定数字引文、GB/T 7714参考文献及结果交叉
引用清单。DOCX 生成阶段会把 `[[BOOKMARK:目标|标题]]` 和 `[[REF:目标|显示文本]]`
转换为 Word 原生书签及 `REF` 域，打开文档时自动更新域；缺失目标、重复目标、残留标记
或无效 REF 都会阻断交付。内置模板本身也已修复到严格 OOXML 校验通过。

## 9. 后台作业与预算治理（已实现）

`backend/jobs/` 为环执行、分节生成和 DOCX 生成提供持久化 JobRun。作业由 SQLite
保存，通过幂等键去重；Worker 用租约和周期心跳声明所有权，进程中断后过期租约会按
最大尝试次数恢复或失败。排队作业可立即取消，运行中作业在 LLM 调用边界协作取消。

每个作业可设置 Token 与费用上限。LLM 请求前按输入估算和最大输出做预算预检，响应后
优先读取供应商真实 usage，缺失时才保守估算，并将输入/输出 Token、费用和剩余额度写回
JobRun。价格不写死在代码中，必须通过环境变量配置当前模型单价。作业 ID 与最终使用量
会进入 `ContextManifest`，从阶段产物可反查本次生成成本。

## 10. 作者工作台（已实现基础交互）

右侧项目工作台已接入真实证据、分节和 JobRun API：作者可查看论证覆盖、来源核验状态、
分节完整性、各节最新版本与审批状态；可生成、修订、批准或驳回分节，并查看/取消/重试
后台作业和 Token/费用用量。环执行默认入队，不再占用同步 HTTP 请求。

界面包含可恢复的加载/空/网络错误状态，页签支持方向键，模态具备焦点陷阱与焦点恢复，
动态状态通过 live region 宣告。作者修订不会覆盖旧内容，而是创建新版本并重新执行引用
指纹 Gate。
