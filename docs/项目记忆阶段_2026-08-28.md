# 论文级项目记忆阶段

## 目标与边界

项目记忆用来保存跨环节稳定的作者事实，不保存API Key、原始实验数据或未脱敏个人信息。当前记忆包含：

- 研究问题；
- 作者/导师/团队决定及理由；
- 导师意见、处理状态和回应；
- 术语的原形、规范表达、定义和禁用别名；
- 语言、语气、人称、时态、引用样式和其他写作约束。

## 版本与审批

`PROJECT_MEMORY`使用现有`ArtifactRegistry`保存，每次修订都创建不可变新版本：

1. 前端或API提交内容；
2. Pydantic校验字段、长度、重复研究问题和重复术语；
3. 通过自动门禁后进入`WAITING_APPROVAL`；
4. 作者批准后成为唯一`APPROVED`版本；
5. 新版本批准时，旧批准版本转为`SUPERSEDED`。

未批准、被驳回、过期或已替代版本不会进入Agent上下文。

## API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/console/tasks/{task_id}/memory` | 创建待审批版本 |
| `GET` | `/api/v1/console/tasks/{task_id}/memory` | 列出全部版本与状态 |
| `POST` | `/api/v1/console/tasks/{task_id}/memory/{artifact_id}/review` | 批准或驳回版本 |

安全模式下，端点继续复用任务租户隔离和`owner/editor/reviewer/viewer`权限规则；`viewer`不能修改或审批。

## Agent消费规则

环6启动时只查询当前有效批准版本。如果存在：

- 写作计划Agent必须调用`read_approved_context(kind=project_memory)`；
- 未读取则整个计划失败，不会静默忽略记忆；
- 计划检查点记录记忆产物ID和已读上下文类型；
- 逐章写作提示也注入同一批准版本，并受长度上限保护。

当前只对环6强制消费；其他环节在后续有界Agent扩展时接入。

## 前端交互

右侧工作台新增“记忆”页签，支持创建、批准、驳回、查看摘要与“基于此版修订”。表单错误与字段通过`aria-describedby`、`aria-invalid`和断言式实时区域关联；页签支持键盘左右键切换。

真实浏览器验收覆盖了空研究问题错误、版本生成、状态刷新和作者批准。验收发现并修复了2个异步事件引用问题，修复后浏览器控制台0错误、0警告。
