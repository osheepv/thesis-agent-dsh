## 1. 业务背景与价值

### 1.1 业务背景

- **当前业务现状**：研究生与科研人员撰写学位论文（本科 / 硕士 / 博士）周期长、返工率高，尤其在结构规范、格式排版、引用真实性、查重合规等方面依赖大量人工核对与经验判断。行业普遍存在伪引、张冠李戴、转引不核对、格式被退回等硬伤。
- **触发本次需求的事件**：AI 辅助写作已成刚需，但通用 AI 工具（纯 Prompt 编排类）缺乏「论文特有流程」的可校验、可回退、可审计管控，无法可靠表达十环节状态机、本硕博差异路由与回退环路，且存在跨阶段漂移、难审计、易出伪引等硬伤（research_report §3.2，O1 纯 Prompt 得分 2.60）。因此需要一个以流程状态机为核心、以真实数据源（万方）为依归、以合规红线为底线的学位论文全流程写作 Agent。
- **本系统在产品矩阵中的位置**：本系统在「学位论文全流程写作价值主线」中承担**核心流程编排与合规底线**职责，与上游 DSH（LLM 运行底座）、万方（真实数据源）、docx 引擎（模板导出 / 校验）、本地存储（会话 / 知识库 / 版本快照）形成完整业务闭环（高层架构 §5.2、§5.3）。

**产品形态一句话**：以自研 FSM 编排层掌控「选题→成稿」十环节流程控制权，DeepSeek-Harness 仅作底层 LLM 运行依赖（不 fork、不大改），业务结构化数据独立落库，按用户自定义 Word 模板导出合规 docx，并以会话绑定式专属知识库（REQ-KB）支撑文献 / 笔记沉淀。

> 本节按七段式（业务场景 / 业务流程 / UE 原型 / 业务逻辑 / 数据描述 / 验收标准 / 外部集成接口）逐条展开。
> 所有 US 均处于非敏感环节，用户无需逐字确认；敏感环节（环节 2/4/8/10）在对应 US 中体现「人工确认浮层弹窗、其余全自动」的交互差异（U-04 已冻结）。

### 5.1 US-1：新建论文会话 → 自动创建绑定知识库并上传解析自定义 Word 模板

#### 5.1.1 业务场景

- **视角**：学生（本科 / 硕士 / 博士）
- **描述逻辑**：学生启动一次新的学位论文写作任务时，首先初始化 FSM 项目（设定学科领域、学位等级、导师方向、兴趣点），并上传自己学校 / 期刊要求的自定义 Word 模板。系统需要在这一步自动创建与会话强绑定的专属知识库，识别模板的版式规范（字体 / 行距 / 页边距 / 页眉页脚 / 前置件顺序），为后续环节 9 导出合规 docx 做准备。

#### 5.1.2 业务流程

- **视角**：用户
- **描述方式**：Given / When / Then 表述当前用户旅程的产品表现流程
  - Given 学生进入「新建论文任务」页面，且已选择学位等级（本科 / 硕士 / 博士）
  - When 学生填写学科领域、导师方向、兴趣点，并点击「创建会话」
  - Then 系统自动创建绑定知识库（知识库 ID 与会话 ID 强绑定），并进入十环节初始状态（全部 NOT_STARTED）
  - When 学生上传自定义 Word 模板文件
  - Then 系统解析模板版式规范，返回「可识别的格式摘要」（字体 / 字号 / 行距 / 页边距 / 前置件清单），并标记模板解析成功 / 失败
  - When 模板解析失败（无法识别 / 文件损坏 / 非 Word 格式）
  - Then 系统返回明确错误原因与修复指引，允许重新上传或更换模板，且不丢失已填写的会话信息

#### 5.1.3 UE 原型

- 核心路径：新建任务向导（学科领域 → 学位等级 → 导师方向 → 兴趣点 → 上传模板 → 模板解析摘要 → 进入工作台）为一步到位的表单流；模板解析结果以「样式规范卡片 + 异常提示占比」呈现。
- 关键节点：上传区（拖拽 / 选择文件）、解析状态反馈（成功 → 绿色摘要卡；失败 → 红色错误 + 原因 + 重试按钮）、知识库绑定标识（会话 ID ↔ 知识库 ID 强绑定标签）。

#### 5.1.4 业务逻辑

- **视角**：业务系统
- **描述方式**：时序或结构化表述当前用户旅程的业务逻辑流程
  1. 前置校验：校验学位等级、模板文件是否 Word 格式、模板是否可解析；
  2. 创建会话：初始化 FSM 项目（10 环节全部 NOT_STARTED）、写 topic 初始字段（question / scope / degree / noveltyStatus）；
  3. 创建知识库：生成知识库 ID，与会话 ID 强绑定写入绑定关系表（回收站开关默认关闭、保护开关默认关闭）；
  4. 模板解析：调用 docxtpl + openxml-audit 读取模板 OOXML，抽取版式规范（字体 / 字号 / 行距 / 页边距 / 页眉页脚 / 前置件顺序），写入模板规则元数据；
  5. 返回解析摘要并进入工作台状态机。
- **安全校验**：模板文件做类型 / 大小 / 内容安全检查；上传内容不得含恶意指令；解析失败需记录 error 原因供审计。

#### 5.1.5 数据描述

- 核心数据流转：`学位等级（Degree）`、`任务上下文（Topic）`、`模板规则元数据（TemplateSpec）`、`会话 ↔ 知识库绑定关系（KB-Binding）`。
- 持久化：业务数据独立落库（t_thesis_task / t_topic / 模板规则元数据），知识库目录独立存放（不与会话日志混合）。

#### 5.1.6 验收标准 AC

- 正常路径：
  - Given 学生已选择学位等级并上传一个有效的 Word 模板
  - When 点击「创建会话」
  - Then 系统成功自动创建绑定知识库，知识库 ID 与会话 ID 强绑定，且十环节初始状态为 NOT_STARTED
  - Given 模板文件为规范 Word 文档
  - When 系统完成模板解析
  - Then 返回可识别的格式摘要（含字体 / 行距 / 页边距 / 前置件清单），且摘要信息完整可读
- 异常路径：
  - Given 上传的模板文件损坏或非 Word 格式
  - When 系统尝试解析
  - Then 返回明确错误原因与修复指引，允许重新上传或更换模板，且已填写的学科 / 学位 / 导师信息不丢失
  - Given 模板无法被识别（格式规范缺失）
  - When 解析失败
  - Then 系统以「降级默认模板」方式继续，并明确标注「当前模板未完全识别，导出可能需人工核对」提示
  - Given 用户删除会话
  - When 触发删除（保护开关默认关闭）
  - Then 系统同步删除绑定知识库，并保留本地回收站 7 天可恢复

#### 5.1.7 外部集成接口

- docxtpl：模板驱动解析生成（需支持中文字体 / 东亚洲字体设置）；
- openxml-audit：OOXML schema / roundtrip 校验，捕获「会打不开 / 被 Word 修复」的损坏输出；
- 本地存储：业务数据 / 知识库独立目录持久化。

### 5.2 US-2：环节 1 选题 + 环节 2 新颖度评估（HITL 确认 + 本硕博路由 + 回退）

#### 5.2.1 业务场景

- **视角**：学生（本科 / 硕士 / 博士）
- **描述逻辑**：学生在环节 1 根据自己的学科领域、导师方向、兴趣点确定候选题目；进入环节 2 由系统对接真实数据源（万方）评估新颖度（别人是否已做过、做得如何、还有没有空间）。学位等级决定创新要求（本科限定问题、硕士明确创新点、博士原创贡献）。本环节是「回退枢纽」，也是敏感环节之一——需人工确认选题方向与创新点定位。

#### 5.2.2 业务流程

- **视角**：用户
- **描述方式**：Given / When / Then 表述当前用户旅程的产品表现流程
  - Given 学生进入环节 1 选题页，系统已读取学科 / 学位 / 导师方向 / 兴趣点
  - When 学生点击「生成候选题目」
  - Then 系统按本硕博路由生成不少于 1 个候选题目，每个附拟解决问题、研究范围边界、一句「为什么值得做」
  - When 学生选择一个候选题目并进入环节 2 新颖度评估
  - Then 系统对接万方检索，输出新颖度结论（高 / 中 / 低）+ 风险说明 + 是否放行的标志
  - When 环节 2 给出结论后触发敏感环节人工确认（HITL 弹窗）
  - Then 弹窗展示「确认选题方向 / 创新点定位」，学生确认放行 → 推进环节 3；确认不通过 → 回退环节 1 换题或收敛
  - Given 新颖度结论为「低」（同题已有人做且成熟）
  - When 学生选择「换个角度 / 换场景 / 换方法」
  - Then 系统回退到环节 1 重新生成候选题目，并保留原话题上下文

#### 5.2.3 UE 原型

- 核心路径：环节 1 选题（候选题目卡片 + 一键生成 / 调整）→ 环节 2 新颖度评估（结论 + 相似研究清单 + 局限说明）→ 敏感环节确认浮层（确认选题方向 / 创新点定位，通过 / 打回）。
- 关键节点：候选题目卡片（拟解决问题 / 范围 / 为什么值得做）、新颖度结论 + 风险说明、本硕博差异化标签（本科「限定问题」/ 硕士「明确创新点」/ 博士「原创性贡献」）、回退入口。

#### 5.2.4 业务逻辑

- **视角**：业务系统
- **描述方式**：时序或结构化表述当前用户旅程的业务逻辑流程
  1. 选题生成：调用环节执行体「选题」，按 degree 路由参数（bachelor / master / phd）控制题目规模（限定 / 中等 / 体系化）与创新义务（有一点想法 / 明确创新点 / 原创性贡献）；
  2. 新颖度评估：调用万方「研究前沿脉络库」「新兴主题库」「选题评估」，检索同题 / 近题及局限，输出 novelty（高中低）+ noveltyStatus（放行 / 回退）；
  3. 本硕博差异化：创新性门槛（极低 / 中（硬性要求）/ 极高（决定性要求））、创新类型（有个想法即可 / 方法改进·场景迁移·模型适配·数据新 / 新理论·新方法·新发现·新体系）、是否需回答「前人为何没做到」（否 / 简单提及 / 必须系统论证）；
  4. HITL 插桩（环节 2）：若系统判定为敏感确认点，则暂停并抛出人工确认浮层；学生确认放行 → accept = true 推进入口；确认打回 → fallbackTo = 环节 1，带前驱指针保留上下文（原话题可编辑）；
  5. 万方可信边界：显示 50 代表「至少 50 篇、具体多少未知」，仅少于 50 才是真实召回量（看页数 = 5 页即撞上限、不满 5 页才是真值）；「没查到」需区分「库中无沉淀（利好信号）」与「网络超时（标注『本次未纳入』）」；严禁把「没查到」当「没人做过」。
- **红线校验**：新颖度结论必须基于真实取数（万方），禁止大模型凭空编造文献或查新结论（Guardrail 置顶）。

#### 5.2.5 数据描述

- 核心数据流转：`Topic（question / scope / degree / novelty / noveltyStatus）`、`NoveltyResult（结论 / 风险 / 相似研究清单 / 检索范围）`、`guardrailLog（学术不端 / 编造查新红线条目）`。
- 持久化：topic、noveltyResult 独立落库；检索范围（数据库 / 时间窗 / 关键词组合）需记录以便复核。

#### 5.2.6 验收标准 AC

- 正常路径：
  - Given 学生已设置学科 / 学位 / 导师方向 / 兴趣点
  - When 点击「生成候选题目」
  - Then 系统按本硕博路由生成不少于 1 个候选题目，每个含拟解决问题 / 范围 / 为什么值得做
  - Given 学生进入环节 2 且系统完成万方检索
  - When 输出新颖度结论
  - Then 结论标注「真实取数来源（万方）」与「数据可信边界」（50 篇上限 / 没查到分两种）
  - Given 环节 2 触发敏感环节人工确认
  - When 学生确认放行
  - Then 系统将环节 2 状态置为 PASSED，推进环节 3
- 异常 / 回退路径：
  - Given 新颖度结论为「低」（同题已有人做且成熟）
  - When 学生选择「换个角度 / 换场景 / 换方法」
  - Then 系统回退到环节 1，保留原话题上下文并可编辑后重新生成
  - Given 学生确认 HITL 不通过（创新点不满足学位等级要求）
  - When 学生点击打回
  - Then 系统回退到环节 1，并明确提示「按当前学位等级需补足创新点 / 收窄范围」
  - Given 万方接口超时或异常
  - When 系统取数失败
  - Then 系统如实标注「本次未纳入」或降级为「人工输入查新结论」，不编造替代结论

#### 5.2.7 外部集成接口

- 万方开放平台（研究前沿脉络库 / 新兴主题库 / 选题评估 / 学术主题分布 / 关联主题词）；
- 万方询证结论需遵守：50 篇上限、没查到分两种、学科没名字（交叉学科只返回编号不给名称）三条可信边界；
- DSH（LLM 运行底座）驱动选题提示词生成。

### 5.3 US-3：环节 3 文献调研 + 环节 4 文献综述（HITL 确认 + 回退）

#### 5.3.1 业务场景

- **视角**：学生（本科 / 硕士 / 博士）
- **描述逻辑**：学生在环节 3 系统搜集主题相关文献（期刊、硕博论文、专著、会议、报告），构建证据池（文献池）；环节 4 对证据做批判性整合，梳理研究脉络、识别争鸣与空白，为论文立论并包住创新点。本环节是敏感环节之一——需人工确认研究空白与切入角度。概览性综述（本科）到批判性综述（博士）差异显著。

#### 5.3.2 业务流程

- **视角**：用户
- **描述方式**：Given / When / Then 表述当前用户旅程的产品表现流程
  - Given 学生已通过环节 2 放行，进入环节 3 文献调研
  - When 系统按主题关键词 + 学位等级检索（万方文献库 / 学者库）
  - Then 生成文献清单（题录 + 摘要 + 分类：理论 / 方法 / 实证 / 综述），并按「文献数量与深度」本硕博路由（本科量少够用约 30 篇 / 硕士主干 + 近年 50~80 篇 / 博士穷尽主干 + 国际前沿百篇级且精读经典）
  - When 环节 3 验收通过
  - Then 系统自动将合格文献写入绑定知识库（携带 GB/T 7714 引用格式 + 摘要 + 来源；无下载权限仅存元数据）
  - Given 学生进入环节 4 文献综述
  - When 系统整合文献池输出综述
  - Then 按本硕博路由（介绍性 / 分析性 / 批判性建构立场）生成综述章节
  - When 环节 4 触发敏感环节人工确认（HITL 弹窗）
  - Then 弹窗展示「确认研究空白 / 切入角度」，学生确认放行 → 推进环节 5；确认不通过 → 回退到环节 2 评估或环节 3 补料

#### 5.3.3 UE 原型

- 核心路径：环节 3 文献调研（检索式 + 题录清单 + 分类归档 + 自动入库标识）→ 环节 4 文献综述（综述章节 + 研究现状 + 不足 + 切入角度）→ 敏感环节确认浮层（确认研究空白 / 切入角度，通过 / 打回）。
- 关键节点：文献池列表（题录 + 摘要 + 分类 + 入库状态：自动入库成功 / 仅元数据）、综述结构化展示、回退入口（回环节 2 / 回环节 3 补检索）、本硕博差异标签。

#### 5.3.4 业务逻辑

- **视角**：业务系统
- **描述方式**：时序或结构化表述当前用户旅程的业务逻辑流程
  1. 文献调研：调用万方「文献库检索」「学者库检索」「期刊选题学科分类」，按主题 + 时间窗检索，产出文献池（literaturePool），每条目含 id / title / authors / source / year / vol / issue / pages / category / summary / verified；
  2. 自动入库（REQ-KB）：环节 3 经验收 Gate 通过的检索文献自动写入绑定知识库，携带 GB/T 7714 引用格式 + 摘要 + 来源；无下载权限文献仅存元数据；强制写入版权提示（仅限个人学习）；单库文献数量上限校验；
  3. 文献综述：调用环节执行体「综述」，按 degree 路由控制综述性质（介绍性 / 分析性 / 批判性）、是否含「自己的框架」、是否需要「评」、是否覆盖国际前沿；
  4. HITL 插桩（环节 4）：敏感确认浮层；确认放行 → accept = true；确认打回 → fallbackTo（序号 4 环回退：综述冲突 → 环节 2 重评估；综述证据不足 → 环节 3 补检索）；
  5. 万方可信边界：文献量按页数判断召回（50 篇上限）；「没查到」区分两种；引用需区分一手 / 二手综述以一手为主。
- **红线校验**：严禁虚假文献、张冠李戴、掐头去尾；仅允许「文献调研经 Gate 验收的检索文献」与「用户手动笔记」入库，对话日志 / 调试流水 / 闲聊禁止自动入库。

#### 5.3.5 数据描述

- 核心数据流转：`LiteraturePool（题录 + 摘要 + 分类 + verified）`、`LiteratureReview（综述章节 / 研究现状 / 不足 / 切入角度）`、`KB-Entry（文献实体 / 用户笔记实体，双链 + 关联类型）`。
- 持久化：literaturePool、review 独立落库；知识库独立目录。

#### 5.3.6 验收标准 AC

- 正常路径：
  - Given 学生已通过环节 2 并进入环节 3
  - When 系统完成文献检索
  - Then 生成按「理论 / 方法 / 实证 / 综述」分类的文献池，且记录检索式可回溯
  - Given 环节 3 验收通过
  - When 系统自动入库
  - Then 合格文献写入绑定知识库（携带 GB/T 7714 + 摘要 + 来源），无下载权限文献仅存元数据且标注版权提示
  - Given 学生进入环节 4 且系统完成综述
  - When 触发敏感环节人工确认
  - Then 展示「确认研究空白 / 切入角度」，学生确认放行后推进环节 5
- 异常 / 回退路径：
  - Given 综述暴露创新点已有人做
  - When 学生确认打回
  - Then 系统回退到环节 2 重评估（很可能换角度），保留对话 / 文献池上下文
  - Given 综述证据不足
  - When 学生选择补检索
  - Then 系统回退到环节 3，扩充同义词 / 放宽时间窗 / 跨学科检索
  - Given 用户尝试将对话日志 / 闲聊手动入库
  - When 系统检测到非「经 Gate 验收文献 / 用户笔记」
  - Then 阻止自动入库，仅允许用户显式指令手动存入对话片段

#### 5.3.7 外部集成接口

- 万方开放平台（文献库检索 / 学者库检索 / 期刊选题学科分类 / 研究前沿脉络库 / 研究趋势报告）；
- REQ-KB 知识库标准化接口（文献自动入库，Agent 仅新增 + 读取，不可删改）；
- DSH（LLM 运行底座）驱动综述提示词生成。

### 5.4 US-4：环节 5 大纲 + 环节 6 撰写 + 环节 7 润色（本硕博差异路由 + 非敏感全自动）

#### 5.4.1 业务场景

- **视角**：学生（本科 / 硕士 / 博士）
- **描述逻辑**：学生在环节 5 将研究问题拆解为章节结构（章 / 节 / 小节 + 目标字数 + 证据要求）；环节 6 按大纲逐章填充；环节 7 做内容打磨与形式统一。这是最耗时的三段，也是本硕博差异在「研究设计 / 贡献论证」集中体现的一环。三个环节均为非敏感环节，全自动运行、不打断用户。

#### 5.4.2 业务流程

- **视角**：用户
- **描述方式**：Given / When / Then 表述当前用户旅程的产品表现流程
  - Given 学生进入环节 5 大纲页
  - When 系统按研究问题 + 综述结论 + 创新点生成结构化大纲
  - Then 输出到三级标题 + 每节要点 / 目标字数 / 证据要求；按本硕博路由控制章节数（本科 3~5 章 / 硕士 4~6 章 / 博士 5~8 章可含独立成果章节）
  - When 学生确认大纲
  - Then 进入环节 6，按大纲逐章撰写（系统自动分派任务到各章节）
  - When 学生点击某章「生成 / 再生成」
  - Then 系统输出该章节草稿，并标记需求证据（needsEvidence）为可追溯
  - When 学生进入环节 7 润色
  - Then 系统做逻辑 / 语言 / 结构打磨与形式统一（术语、图表、编号），输出润色稿
  - Given 大纲逻辑断链 / 某章贡献与创新点冲突
  - When 学生调整大纲
  - Then 回退到环节 5 重排，补逻辑桥段 / 收敛虚章

#### 5.4.3 UE 原型

- 核心路径：环节 5 大纲结构化编辑（拖拽 / 增删 / 动态扩容，博士可加独立成果章节）→ 环节 6 章节生成 / 撰写页（章节选择、生成 / 再生成、needsEvidence 标记）→ 环节 7 润色页（逻辑 / 术语 / 编号统一）。
- 关键节点：大纲树（章 / 节 / 小节 + 目标字数 / 证据）、章节草稿卡片（状态：生成中 / 已生成 / 需证据）、润色差异对比（原稿 vs 润色稿）、本硕博差异标签（章节数 / 结构自由 / 是否允许独立创新章节 / 对理论框架要求）。

#### 5.4.4 业务逻辑

- **视角**：业务系统
- **描述方式**：时序或结构化表述当前用户旅程的业务逻辑流程
  1. 大纲搭建：调用环节执行体「大纲」，按 degree 路由控制章节数（3~5 / 4~6 / 5~8）、结构自由（模板化 / 结构化 / 可自定义体系）、是否允许独立创新章节 / 专利章（否 / 少 / 是）、对理论框架要求（弱 / 中 / 强）；output = 结构化 outline（chapters 数组含 id / title / objective / evidence / words / contribution）；
  2. 分章节撰写：调用环节执行体「撰写」，按大纲逐章填充；本硕博差异集中在研究设计（方法深度：基础模板 / 成熟方法 / 自建方法体系创新实验；数据 / 实验要求：简单 / 真实可靠可复现 / 体系化多方位验证；创新论证强度：弱 / 中（与已有对比即可）/ 强（系统性论证原创性回答「差在哪」）；
  3. 修改润色：调用环节执行体「润色」，做逻辑 / 语言 / 结构打磨；本硕博差异在语言严谨度（基本通顺 / 规范 / 精炼·深度·有学术功底）、术语体系（宽 / 规范 / 自成体系）、润色重点（通顺 + 规范 / 逻辑 + 专业 / 深度 + 原创性表达打磨）；结构性问题回退到环节 6（乃至 5），文字性问题本环内解决；
  4. 非敏感全自动：本 US 覆盖环节 5/6/7 三个非敏感环节，全自动运行、不打断用户；但部分分支场景（大纲逻辑断链、撰写证据不足、润色发现结构性问题）可触发回退。
- **红线校验**：撰写 / 润色环节须严谨知识归属（观点 / 数据 / 图表有来源，否则环节 8 爆雷）；禁止篡改 / 伪造数据实验（一票否决）；禁止把润色当改写（乱改专业内容影响准确性）。

#### 5.4.5 数据描述

- 核心数据流转：`Outline（chapters 数组含贡献定位）`、`ChapterDraft（chapterId / status / sections / needsEvidence）`、`PolishedDraft（润色稿 + 差异）`。
- 持久化：outline、chapterDraft、polishedDraft 独立落库。

#### 5.4.6 验收标准 AC

- 正常路径：
  - Given 学生进入环节 5，系统已具备研究问题 + 综述结论 + 创新点
  - When 生成大纲
  - Then 输出到三级标题的完整结构，每节含目标字数 / 证据要求，且章节数符合本硕博路由（博士可含独立成果章节）
  - Given 学生确认大纲并进入环节 6
  - When 点击某章「生成」
  - Then 输出该章草稿，并在证据需求点标记 needsEvidence 可追溯
  - Given 学生进入环节 7
  - When 执行润色
  - Then 输出润色稿（逻辑 / 语言 / 结构 / 术语 / 编号统一），且保留原稿可对比
- 异常 / 回退路径：
  - Given 大纲逻辑断链
  - When 学生调整
  - Then 系统回退到环节 5 重排，补逻辑桥段
  - Given 某章证据不足、论证空洞
  - When 学生标记
  - Then 系统回退到环节 6 / 环节 5 / 环节 3 补证据（数据 / 文献 / 实验）
  - Given 润色发现结构性 / 逻辑性问题
  - When 学生选择回退
  - Then 系统回退到环节 6（乃至 5），文字性问题在本环内解决

#### 5.4.7 外部集成接口

- REQ-KB 知识库（综述、撰写环节 Agent 优先检索当前绑定知识库内容）；
- DSH（LLM 运行底座）驱动大纲 / 撰写 / 润色生成；
- 万方文献库（如需补「最新研究现状」可回查，非强外部取数）。

### 5.5 US-5：环节 8 引用 / 参考文献校验（HITL 确认 + 伪引回退）

#### 5.5.1 业务场景

- **视角**：学生（本科 / 硕士 / 博士）
- **描述逻辑**：学生在环节 8 对全文引用与文末参考文献做真实性、准确性、一致性核验。这是「最容易出学术不端与硬伤的一环」，也是敏感环节之一——需人工确认无伪引、引用真实。本硕博差异在文献量、外文 / 国际文献、引用体例规范、对引用准确性容忍（低 / 中 / 零容忍）。

#### 5.5.2 业务流程

- **视角**：用户
- **描述方式**：Given / When / Then 表述当前用户旅程的产品表现流程
  - Given 学生进入环节 8 引用核验页
  - When 系统扫描全文正文引点与文末参考文献
  - Then 建立引用映射（正文引点 ↔ 文末文献一一对应），并做真实性反查（对接万方文献库按题录反查）
  - When 检出伪引 / 题录错误 / 格式体例混用
  - Then 伪引标红、题录错误定位、体例混用提示；伪引必须删除（红线）
  - When 环节 8 触发敏感环节人工确认（HITL 弹窗）
  - Then 弹窗展示「确认无伪引、引用真实」，学生确认放行 → 推进环节 9；确认打回 → 回退到环节 3/4 找替代真实文献
  - Given 检出被引文献不可回溯
  - When 系统判定是「信息错误」还是「伪引」
  - Then 伪引删除并回退到环节 3/4 找替代真实文献；信息错误则本环内回查修正

#### 5.5.3 UE 原型

- 核心路径：环节 8 引用核验页（正文引点 ↔ 文末文献一一对应核验、真实性反查结果、伪引标红、一键修正）→ 敏感环节确认浮层（确认无伪引、引用真实，通过 / 打回）。
- 关键节点：引用映射表（正文引点 ↔ 文末文献、检查状态）、真实性反查结果（真实 / 存疑 / 伪引）、伪引标红列表体例、本硕博差异标签（文献量 / 外文占比 / 引用体例规范 / 准确性容忍）。

#### 5.5.4 业务逻辑

- **视角**：业务系统
- **描述方式**：时序或结构化表述当前用户旅程的业务逻辑流程
  1. 建立引用映射：遍历正文引点与文末文献集合，构建 citationMap（inTextRefId → bibRefId, checked）；双向核对（无引而列、无列而引均视为缺漏）；
  2. 真实性反查：调用万方「文献库检索」按题录反查，确认篇名 / 作者 / 刊名 / 年份 / 卷期页是否存在且一致；不可回溯时判断是「信息错误」还是「伪引」；
  3. 体例规范：按 GB/T 7714-2015（或学校 / 期刊指定体例）统一格式；作者超 3 人「等」处理；区分学位论文 / 专著 / 会议 / 报告类别标识；
  4. 本硕博差异：文献数量（少 / 中 / 多而深）、外文 / 国际文献（少 / 中 / 大量）、引用体例规范（基本规范 / 严格 / 极严格）、对引用准确性容忍（低 / 中 / 零容忍）；
  5. HITL 插桩（环节 8）：敏感确认浮层；确认放行 → accept = true；确认打回 → fallbackTo（伪引 → 环节 3/4 找替代真实文献；题录错误 → 本环内回查修正）。
- **红线校验**：伪引 / 幽灵文献是学术不端一票否决项；严禁转引不核对、张冠李戴。

#### 5.5.5 数据描述

- 核心数据流转：`citationMap（inTextRefId → bibRefId, checked）`、`参考文献库（题录准确 / 格式规范 / 与正文一一对应）`、`guardrailLog（伪引红线条目）`。
- 持久化：citationMap、文献库独立落库。

#### 5.5.6 验收标准 AC

- 正常路径：
  - Given 学生进入环节 8
  - When 系统扫描全文
  - Then 建立正文引点 ↔ 文末文献一一对应映射，真实性反查结果标注「真实取数来源（万方）」
  - Given 全部引用真实且体例规范
  - When 触发敏感环节人工确认
  - Then 弹窗展示「确认无伪引、引用真实」，学生确认放行后推进环节 9
- 异常 / 回退路径：
  - Given 检出伪引
  - When 学生确认打回
  - Then 伪引删除并回退到环节 3/4 找替代真实文献
  - Given 引用与文末不匹配（无引而列 / 无列而引）
  - When 系统检测到缺漏
  - Then 双向核对修正，提示补齐或删除对应条目
  - Given 格式体例混用（GB/T 7714 与 APA、IEEE 混用）
  - When 系统检测到
  - Then 提示全文统一
  - Given 被引文献不可回溯且判定为「伪引」
  - When 系统删除
  - Then 记录到 guardrailLog 并回退补真实文献
  - Given 引用题录信息错误 / 缺失
  - When 系统定位
  - Then 回查补全（本环内修正）

#### 5.5.7 外部集成接口

- 万方开放平台「文献库检索」（按题录反查）；
- REQ-KB：Agent 优先检索当前绑定知识库内容；
- DSH（LLM 运行底座）驱动引用核验提示词。

### 5.6 US-6：环节 9 格式排版 + 环节 10 最终定稿（HITL 确认 + 版本快照 + 查重回退）

#### 5.6.1 业务场景

- **视角**：学生（本科 / 硕士 / 博士）
- **描述逻辑**：学生在环节 9 将稿件按学校 / 学位要求的版式规范排版（字体、字号、行距、页边距、页眉页脚、图表、目录、页码、前后置件），并导出合规 docx；环节 10 做全稿最终一致性、完整性、合规性检查，确认达到送审 / 答辩标准，并归档可提交版本。环节 10 是敏感环节之一——需人工确认整体合规、查重风险。

#### 5.6.2 业务流程

- **视角**：用户
- **描述方式**：Given / When / Then 表述当前用户旅程的产品表现流程
  - Given 学生进入环节 9 格式排版页
  - When 系统按用户上传的自定义模板解析并排版
  - Then 按模板样式规范输出排版稿，并做 OOXML schema / roundtrip 校验（捕获损坏输出）
  - When 学生点击「导出 Word」
  - Then 系统生成合规 docx，前置件顺序正确（封面 → 原创声明 → 中文摘要 → 英文摘要 → 目录 → 正文 → 参考文献 → 附录 → 致谢，按学校要求）
  - When 学生进入环节 10 最终定稿
  - Then 系统做全流程 10 环验收项汇总检查（选题清晰 / 新颖度达标 / 文献充分 / 综述批判 / 大纲闭环 / 论证可靠 / 润色到位 / 引用准确无伪引 / 排版规范）
  - When 环节 10 触发敏感环节人工确认（HITL 弹窗）
  - Then 弹窗展示「确认整体合规、查重风险」，学生确认放行 → 生成版本快照归档；确认打回 → 回退对应环节
  - Given 查重超限 / 材料不齐 / 格式与正文不一致
  - When 学生确认打回
  - Then 回退到对应环节（查重超限 → 环节 6/7/8；材料不齐 → 补齐；格式 / 正文不一致 → 环节 6/8）

#### 5.6.3 UE 原型

- 核心路径：环节 9 格式排版页（版式规范校验 + 导出合规 docx + 样式差异提示）→ 环节 10 最终定稿（全流程 10 环验收项汇总 + 版本快照归档）→ 敏感环节确认浮层（确认整体合规、查重风险，通过 / 打回）。
- 关键节点：版式规范校验结果（前置件顺序 / 字体字号 / 行距 / 页边距 / 页眉页脚 / 目录页码一致性）、导出状态反馈（成功 / 损坏输出告警）、10 环验收项总览（逐项通过 / 未通过）、版本快照时间戳、查重提醒提示（提醒用户自建查重）。

#### 5.6.4 业务逻辑

- **视角**：业务系统
- **描述方式**：时序或结构化表述当前用户旅程的业务逻辑流程
  1. 格式排版：调用 docx 模板编排（M6），解析用户自定义模板，按模板样式规范排版；调用 openxml-audit 做 schema / roundtrip / load 校验（捕获损坏输出）；本硕博差异在排版严格度（中 / 高 / 极高含盲审格式）、前置件（相对简单 / 标准齐全 / 需更多如创新点声明答辩材料）、摘要 / 关键词（基本 / 规范 / 严格）；
  2. 导出合规 docx：按用户自定义模板解析并导出，保留格式、所见即所得；页数 / 篇幅按学位等级（少 / 中 / 大）；
  3. 最终定稿：全流程 10 环验收项汇总检查 + 查重结果满足学校阈值（未超限、引用已规范处理）+ 关键材料齐备（承诺书、论文、附件、答辩 PPT 按需）+ 全文一致性（题目 / 摘要 / 正文 / 结论表述一致无信息矛盾）；
  4. HITL 插桩（环节 10）：敏感确认浮层；确认放行 → accept = true 并生成版本快照归档；确认打回 → fallbackTo（查重超限 → 环节 6/7/8；评审 / 盲审意见 → 回相应环节；格式 / 材料不齐 → 补齐）；
  5. 版本快照：生成过程版本（供回退 / 审计），保留可追溯状态。
- **红线校验**：查重合规（引用规范处理，重复率低于学校红线）；提交前查重与学位授予要求逐项核对；保留过程版本。

#### 5.6.5 数据描述

- 核心数据流转：`TypesetDoc（排版稿 + 校验结果）`、`版本快照（VersionSnapshot，过程版本供回退 / 审计）`、`全流程验收项汇总`。
- 持久化：typesetDoc、versionSnapshot 独立落库；导出 docx 为文件输出。

  - When 系统解析并排版
  - Then 按模板样式规范输出排版稿，且通过 OOXML schema / roundtrip 校验（无损坏输出）
  - Given 学生点击「导出 Word」
  - When 系统导出
  - Then 生成合规 docx，前置件顺序正确，与用户模板样式一致
  - Given 学生进入环节 10 且全流程 10 环验收通过
  - When 触发敏感环节人工确认
  - Then 弹窗展示「确认整体合规、查重风险」，学生确认放行后生成版本快照归档
- 异常 / 回退路径：

### 5.7 US-7：会话绑定式知识库 REQ-KB 用户操作（笔记 / 双链 / 标签 / 检索 / 批量导出 / 图谱 / 权限 / 回收站）

#### 5.7.1 业务场景

- **视角**：学生（本科 / 硕士 / 博士），以及系统运营 / 模板管理员

## 6. 非功能性需求

> 本节回收易用性、性能、操作与环境、安全性四类非功能需求，对齐高层架构 §6.4 关键交互约束与 V1/V3 目标。

### 6.1 易用性需求

- **操作便利性**：
  - 核心路径：从「当前环节」到「完成并推进下一环节」主路径少于或等于 5 步（对齐高层架构 §6.4）；
  - 模板上传提供拖拽 / 选择文件双入口，解析失败给出明确原因 + 重试 / 更换模板指引，且不丢失已填写的会话信息；
  - 敏感环节人工确认浮层（环节 2/4/8/10）以「确认放行 / 打回」两态呈现，减少误操作。
- **UI 一致性**：
  - 十环节状态机全貌用统一色标（进行中 / 通过 / 回退），环节卡片点击进入；各页面（写作者工作台 / 导师审阅端 / 管理看板 / 知识库）遵循统一组件规范与术语（对齐 `_runtime_meta.md` §2 术语表）。
- **引导提示**：
  - 本硕博差异、回退状态、知识库绑定、数据可信边界（50 篇上限 / 没查到分两种）均以明确提示标注，杜绝编造式结论；
  - 首次使用提供新建会话向导 + 十环节说明，降低上手成本。
- **错误反馈**：
  - 解析失败 / 导出损坏 / 伪引 / 红线命中均给出明确错误信息 + 修复指引，而非静默失败；
  - 万方接口异常时如实标注「本次未纳入」或降级为「人工输入查新结论」，不编造替代结论。
- **无障碍支持**：
  - 关键确认按钮支持键盘可达，文本 / 图标双通道提示；页面层级清晰、可读性良好。

### 6.2 性能响应需求

- **关键接口响应时延**：
  - 敏感环节 HITL 响应：触发到呈现 P99 少于或等于 3 秒（对齐高层架构 §6.4，V1/V3）；
  - 模板解析接口：P50 少于或等于 2 秒、P99 少于或等于 8 秒（经验量级估算，实际以运行观测为准；若上游未给基线，此值需人工确认，不作为 SLA 隐性承诺）。
- **吞吐量 / 并发用户数**：
  - MVP 单机本地部署，面向国内教学 / 科研场景；单机初期并发用户数按少于 50 设计（经验量级估算，非 SLA 承诺）。
- **数据规模上限**：
  - 万方文献检索召回上限（50 篇）；知识库单库文献数量上限（建议默认 2000 条，具体取值需人工确认）；
  - 图谱可视化仅前端按需实时渲染，后台不持续运算，避免阻塞主流程（对齐 _runtime_meta §8.3）。

### 6.3 操作与环境需求

- **浏览器 / 客户端兼容性**：
  - 支持主流通用浏览器（Chrome / Edge / Firefox 近两年稳定版本）。
- **网络环境**：
  - 本地 / 私有化部署，MVP 单机；万方接口异常时如实回避、降级为「人工输入查新结论」，不阻塞主流程。
- **设备规格**：
  - 面向教学 / 科研场景的常规桌面设备；docx 导出依赖 docxtpl（无需用户安装 Word），openxml-audit 校验捕获损坏输出。
- **运行环境约束**：
  - Python 运行底座（依赖 DSH / docxtpl / openxml-audit）；数据默认本地存储、独立目录（知识库与会话日志 / FSM 状态分离）。

### 6.4 安全性需求

> 满足相关安全标准（对齐高层架构 §6.4 与 material_digest §0.3 全局红线）。

#### 6.4.1 安全密码设置

- 产品若涉及账号密码设置功能，需要支持达到以下设置强度：**最小长度 12 位，包含大小写字母 + 数字 + 特殊字符**（对齐系统设计 §7.2.1 全局安全基线）。

#### 6.4.2 安全软件架构

- 应保证自身结构中各模块的通信安全；
- 应保证组件、用户、资源的认证与访问控制；
- 当应用系统存在与外部其他应用系统进行交互时，应保证应用系统与外系统接口的安全，包括：限制未经许可的接口访问；使用适当的加密与认证手段；限制外部应用系统所能获取的内容，使用安全的通讯协议。

#### 6.4.3 安全设计

- 应提供认证授权功能。

#### 6.4.4 安全开发

- 应对函数入口参数的合法性和准确性进行检查；
- 应进行输入边界检查，限制输入的正确长度和格式；
- 应保证不因代码的编写导致出现可被直接利用的高危漏洞；
- 应在应用系统输入输出模块中进行适当的过滤，以防范恶意指令和内部信息泄露；
- 禁止使用未经授权和验证的代码；
- 应保证应用程序不存在任何可绕行安全机制的行为或遗留后门。

#### 6.4.5 安全测试和部署

- 应进行安全扫描测试；
- 应进行安全配置基线检查；
- 应进行安全功能的测试；
- 系统在上线前应不存在高危风险。

#### 6.4.6 数据安全

- **数据存储和传输加密**：应在用户密码、身份鉴别信息等重要数据的存储、传输过程进行适当加密，保障信息不被泄露。
- **REQ-KB 内容与权限安全**（对齐 _runtime_meta §8）：
  - 知识库默认本地存储、独立目录，不和会话日志 / FSM 业务状态混合存放；
  - Agent 仅拥有【新增调研文献、读取全库】权限，不可修改 / 删除知识库已有条目，编辑 / 删除权限完全交给用户；
  - 强制写入版权提示（仅限个人学习）；自动下载前校验文献权限；
  - 跨会话禁止访问其他知识库（仅用户手动挂载其他独立库后方开放跨库读取）；会话 / 知识库删除后回收站保留 7 天可恢复，逾期永久清除。
