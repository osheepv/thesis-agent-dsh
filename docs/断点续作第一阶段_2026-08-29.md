### 6.1 断网恢复：本次验收发现并修复的真实缺陷

**症状**：在断网期间刷新页面 + 切换页签时，前端 `pagehide` keepalive 保存会把“`last_task_id=''`、`active_tab='<用户切换的页签>'`”的降级状态回写到服务端，把用户原本有效的恢复位置清空。

**证据（修复前）**：
```
$ curl .../workspace
{"workspace":{"last_task_id":"","active_tab":"evidence",...,"updated_at":"2026-08-29T16:44:48.709473Z"}}
```

**修复**：
- 新增 `workspaceServerLoaded` / `sessionListLoaded` / `workspaceRecoveryTrusted` 三态。
- `runWorkspaceSave` 与 `flushWorkspaceSaveOnExit` 必须等待 `workspaceRecoveryTrusted = true`。
- `loadSessions` 成功但工作区读取失败时，**自动重新读取服务端指针**并按该指针重新选择任务。
- 新增 Node 状态流测试 `test_degraded_recovery_never_writes_back_to_server` 与 `test_list_recovery_reloads_server_pointer`，永久锁定回归。

**证据（修复后）**：
```
断网刷新 → aria-live 报告 “论文任务列表加载失败，已保留上次恢复位置”
切换页签：trusted=false → 不发起任何 POST，零写入
后端恢复 + 刷新 → 服务端 updated_at 与断网前一致，指针未被覆盖
viewer 登录：banner 显示自己的任务（租户任务-1），不继承 owner 的（租户任务-2）
```
